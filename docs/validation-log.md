書く形：

```
## YYYY-MM-DD 短い題
- **何を試したか**：端末・着け方・カメラ（広角／超広角）・普段の長さ・場面・時間
- **結果**：観測したこと（数値があれば数値。記録のファイル名があれば書く）
- **分かったこと**：結果から言えること
- **決めたこと**：変えたこと・変えないと決めたこと（理由つき）。まだ決めていなければ「なし」
```

## 2026-10-28 顔の向きの左右を本人から見た右・左にした（v1.7.1）
- **何を試したか**：実機の前面カメラで自分を撮り、自分の右へ頭を傾けた
- **結果**：「左に傾き」と出た。v1.7 までは、向かい合って見る人から見た右（鏡でない映像で見て右）を + にしていたため（前面は v1.6.1 から背面と同じ意味に直していたので、背面で人を撮ったときも、本人が右へ向くと「左」だった）
- **直したこと**：FaceAnalyzer で、変換行列から出した向き（鏡でない映像で見て右が +）の yaw・roll の符号を反対にし、本人から見て右を + にした。前面の鏡の直しはそのまま（その後で反対にする）。
  顔の絵は映像と同じ見え方で描くので、描くときだけ符号を戻す。ヘッダに `direction_version: 2`。それより前の記録は、振り返りレポートとリプレイで読むときに左右を入れ替える（見る側も、古い撮る側から届いたものを入れ替える）。
  作り物の記録（古い形と `direction_version: 2` の形）で、レポートとリプレイの顔の向きの段・head_turn の文が同じになることを確かめた（`DirectionTest`）
- **確かめ方（実機で、まだ）**：前面・背面それぞれで
  1. 本人が自分の右へ顔を向ける（35°より大きく）→「顔の向き：右 ○°（本人から見て）」、0.5秒続くと記録に「右へ」（`head: "right"`、`yaw_deg` が +）。見る側の時間の流れも「右」
  2. 本人が自分の右へ頭を傾ける →「右に傾き ○°（本人から見て）」（`roll_deg` が +）
  3. 左も同じように「左」と出る
  4. 本人が右目だけ閉じる → `eyeBlinkRight` が上がる（表情の Right と向きの右が同じ側か）。逆なら、表情の左右をどちらに揃えるかを決め直す
  5. 顔の絵は、背面で向かい合って見たときと同じ見え方（本人が右へ向くと、絵は画面の左を向く）
  - 背面は、だれかに iPhone を持ってもらって本人の前から撮る
- **決めたこと**：右・左は本人から見た向きに揃える（画面には「（本人から見て）」を付ける）。顔の枠・鍵となる点・網目は映像の中の座標なので変えない

## 2026-10-28 声の高さが普通の声で取れない（v1.6.2）
- **何を試したか**：実機（iPhone を顔から約50cm）で普通に話した4分の記録（2026-10-28）。あわせて、Mac にあった v1.0 より前の記録（iPad、2026-10-27〜28 の 7本）の音量、
  Mac の `say` で作った日本語の声4つ（Kyoko・Grandma・Reed・Grandpa、f0 の中央値 241・99・91・90Hz）と作り物の雑音を、アプリと同じ求め方（`ios/AbilityCam/Pitch.swift`）に流した（`analysis/pitch_check.py`）
- **結果**：
  - 実機の4分の記録で f0 があったのは 105コマ。声の普段の「本人の声 0/10秒」が増えなかった。取れた値に 800Hz・842Hz が混ざっていた
  - 原因：v1.6.1 までは RMS が 0.01（-40dBFS）未満だと f0 を計算しなかった。50cm 離れた普通の声は -45〜-60dB。範囲は 70〜1000Hz で、倍音（声の高さの2倍・3倍の周期）を取り違えても外せなかった
  - Mac の記録の音量（話していない時間を含む）：中央値 -50〜-52dB の記録が5本（p5 -55〜-60）、-63.5dB と -84.5dB が1本ずつ。**部屋の音だけで -55dB を超える部屋がある**ので、音の下限だけでは雑音を除けない
  - 作り物の雑音（白色・ピンク・ブラウン・扇風機のような低い音と 120Hz のうなり・電源のうなり 50Hz・離れた話し声のような揺れる音）を -55・-50・-45・-35dB で各20秒：
    新しい求め方の声らしさ（正規化した自己相関の山の高さ）は最大 0.45（扇風機のような音）、ほかは 0.27 以下。**f0 は 0件**。
    v1.6.1 までの求め方のまま下限だけ -60 に下げると、ピンクの雑音で 53件、ブラウンで 74〜92件 が f0 になった（10秒ずつ）
  - 作り物の声（pink の雑音 -68dB を足す。声らしい塊のうち f0 が取れた割合）：

    | 声の音量（塊の中央値） | 下限 -55dB | 下限 -60dB |
    |---|---|---|
    | -50dB | 0.85〜0.98 | 0.92〜1.00 |
    | -55dB | 0.59〜0.70 | 0.80〜0.95 |
    | -60dB | 0.00〜0.23 | 0.62〜0.71 |

    どちらも、大きい声で取った値と比べて 2倍・半分の取り違えは 0件。500Hz より高い値は 0件（v1.6.1 までの求め方では、同じ声 -45〜-55dB で 577件中 46件が 500Hz より高かった）
  - 扇風機のような音 -62dB を足した声 -45〜-55dB でも、2倍・半分の取り違えは 0件、取れた割合 0.84
- **分かったこと**：雑音を f0 にしないのは、音の下限ではなく声らしさの基準の役目。下限 -55 では、平均 -55dB の声の3〜4割を下限で捨てていた
- **決めたこと**（`criteria.json` の `pitch`、アプリの `PitchCriteria`。ヘッダに `f0_version: 2`・`f0_floor_db`・`f0_range_hz`・`f0_clarity_min`）：
  - **音の下限 -60dBFS**（依頼の -55 より下げた。上の表の理由）。これより小さい音では計算しない
  - **声らしさ 0.6**：正規化した自己相関（NSDF、McLeod の方法）の「鍵となる山」の一番高いものが 0.6 以上のときだけ f0 にする（雑音は最大 0.45）
  - **範囲 70〜500Hz**（話し声）
  - **2倍・半分の取り違えを防ぐ**：一番高い山の 0.9 倍以上の山のうち周期の一番短いものを選ぶ（半分の高さにしない）。それが 500Hz より高ければ f0 にしない（650Hz・900Hz の音を 325Hz・450Hz と出さない）。
    直近1秒の f0 の中央値（3つ以上）から 0.75 オクターブより離れたら、中央値に近い山（一番高い山の 0.7 倍以上）に替える
  - v1.6.1 までの記録の 70〜500Hz の外の f0 は、振り返りレポートとリプレイで読むときに外す（記録の質に「使わなかった値 ○件」）。Mac の記録では 2本で 15件・3件
  - 「数字」に「声の高さが取れた割合（直近10秒、声が出ていたときのうち）」を出す。声が出ていた＝音が -60dB 以上で、直近30秒の静かなときの音（下から1割）より 6dB 以上大きい音の塊（部屋の音が -60dB を超える部屋で、部屋の音を分母に入れないため）
  - 声の普段の進み具合が3秒増えないときは、直近3秒で一番多かった理由を出す：「顔が読めていません」（顔が読めていない）／「声の高さが取れていません」（顔は読めていて f0 が無い）／「口が動いていません」（f0 はあるが口が動いていない）
- **まだ確かめていないこと（実機で）**：
  1. 話していないときの部屋の音（エアコン・冷蔵庫・テレビ）で、「声の高さ Hz」が出ないこと（「数字」で「–」のまま）。電源のうなり 100Hz のような周期のはっきりした音は、声らしさでは除けない
  2. 50cm 離れて普通に話して、「声の高さが取れた割合」が 7割以上になり、声の普段の「本人の声」が増えること
  3. 声の高さの値が話している人の声の高さに近いこと（女性 150〜350Hz・男性 80〜200Hz くらい）、800Hz のような値が出ないこと
  4. 解析コマ/秒が落ちていないこと（f0 の計算は約0.1秒ごと）

## 2026-10-28 前面カメラの向きを直し、保存した普段をカメラごとにした（v1.6.1）
- **何を試したか**：実機の前面カメラで顔をまっすぐ映すと、網目が顔からずれて左下に斜めに出て、顔の向きが「右に傾き 41°」になった（v1.6）
- **結果（原因）**：解析に渡す映像の回転（`videoRotationAngle = 90`）を、カメラの組み替え（入力の付け替え）の途中で決めていた。前面に替えると新しいつながりにその回転が効かず、
  解析に横倒しの映像が渡っていたと考えられる（網目は映像の座標をそのまま重ねるので、ずれて斜めに出る）。あわせて、前面の鏡の設定を解析とプレビューで別々に切っていた
- **直したこと**：
  - 回転は、組み替えが終わってから決める。背面は今まで通り 90°。前面は `AVCaptureDevice.RotationCoordinator` の水平を保つ角度。届いた映像が横長なら決め直す
  - 鏡はカメラの初めの設定のままにし、プレビューを解析に渡す映像と同じ回転・鏡にする。解析に渡す映像が鏡なら、記録の値（左右の表情・yaw と roll の符号・顔の枠の x・鍵となる点）を背面と同じ意味に直す
  - 記録のヘッダに `camera_orientation_version: 2` と `mirror_corrected`（直したか）を書く。無い前面の記録（v1.5〜v1.6）は向きが合っていなかったので、振り返りレポートに注意を出す
- **確かめ方（実機で、まだ）**：
  1. 前面で顔をまっすぐ映す → 網目が顔に重なり、顔の向きが「正面」（roll がほぼ 0°。「数字」には出ないので、記録の `roll_deg` か顔の向きの表示で見る）
  2. 首を傾ける → 傾けた側に roll が出て、網目がついてくる
  3. 画面の映像で見て右へ顔を向ける → 「顔の向き：右」（背面で人を撮ったときと同じ：映像で見て右）。プレビューが鏡なら、自分の右へ向いたときが「右」になる
  4. 右目だけ閉じる → 背面で人を撮って本人の右目を閉じたときと同じ側（`eyeBlinkRight`）が上がる
  5. 広角で同じことをして、今まで通りか（背面の回転は変えていない）
- **決めたこと**：
  - 保存した普段は、カメラ（広角・超広角・前面）ごとに1つずつ持つ。今あるものはそのカメラの普段として移す。開いたとき・カメラを変えたときは、そのカメラの普段があればすぐ比べ、無ければ画面に出して取り、そのカメラの普段として自動で保存する
  - 声の普段はカメラに関係ないので、人ごとに1つ（どのカメラでも使う）
  - 「普段の間に目を閉じていた時間が長いです」は、数えた時間が10秒を超えてから判定する
