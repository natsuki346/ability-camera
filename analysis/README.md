# 振り返りレポート（PC 用）

Ability Cam の記録（JSONL、`ability-cam.ios.v0.2` 以降）から、**普段（type:"baseline"）から外れた区間**を数値の事実として出す。
本人の気持ちや状態は判断しない。文言と色は `../docs/wording-guide.md` に従う。外部には何も送らない（すべて手元の PC で計算する）。

## 使い方
```sh
cd analysis
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # 初回だけ
.venv/bin/python review.py 記録.jsonl            # ふつうの記録
.venv/bin/python review.py 記録.jsonl --calm     # 「何もしていない記録」→ 区間の数を10分あたりでも出す
```
出力は記録と同じ場所に：
- `記録.html` … レポート（グラフの画像は埋め込み、1ファイル）
- `記録_segments.csv` … 区間の一覧。先頭の `#` 行に、使った基準を書き出している

基準を変えて試す：
```sh
.venv/bin/python review.py 記録.jsonl --set brow_down.start_min_s=0.8 --set all.end_z=1.2
.venv/bin/python review.py 記録.jsonl --start-z 2.5          # すべての指標の start_z を変える
.venv/bin/python review.py 記録.jsonl --criteria 別の基準.json --out-dir 出力先
```
変えられる項目：`smooth_s`（ならし）、`start_z`、`start_min_s`、`end_z`、`end_min_s`。

普段の長さを変えて試す（アプリの設定の 30秒／60秒 を、同じ記録で比べる）：
```sh
.venv/bin/python review.py 記録.jsonl --baseline-s 30                  # 普段を30秒で作り直して区間を数える
.venv/bin/python review.py 記録.jsonl --compare-baseline 30,60         # 記録の baseline 行・30秒・60秒 の区間の数を並べる
.venv/bin/python review.py 記録.jsonl --calm --compare-baseline 30,60  # 何もしていない記録なら、10分あたりも並べる
.venv/bin/python review.py 記録.jsonl --compare-saved                  # 保存した普段と今日の普段のずれと、それぞれの区間の数を並べる（v1.2〜の記録）
```
- 普段は、記録の中の1コマごとの値から作り直す。数えるコマの条件はアプリと同じ（直近1秒で顔が映るコマが半分以上で、そのコマに顔があり、\|yaw\|<35°、開いてから5秒より後）。
  記録の始まりと「普段を取り直す」（`baseline_restart`）から集め始め、数えた時間（前に数えたコマからの幅、0.5秒で切る）が指定の秒数になったら作る。アプリと同じく3コマに1コマで数える
- 声は、そのコマに書かれている値を使う（アプリは新しく計算した音だけを数えるので、n や平均がアプリの baseline 行と少しずれることがある）
- `--baseline-s` を付けると、レポートの本体（区間・通知候補・グラフ）もその普段で数える。`--compare-baseline` は、本体とは別に「普段の長さの比べ」の表を足し、画面にも1行ずつ出す
- 普段が短いほど早く判定を始めるので、判定した時間も変わる（区間の数だけでなく、10分あたりで比べる）
- 顔の向きが無い記録（v0.3 より前）は作り直せない

## これまでの記録（`sessions.py`）
アプリは、開いてから閉じるまでを1回の記録（セッション）として `ability-cam-日時.jsonl` に記録し、閉じたときに要約を `sessions.jsonl` に1行足す。
「ファイル」アプリの Ability Cam フォルダを丸ごと PC に写して、フォルダを渡す。
```sh
.venv/bin/python sessions.py Ability\ Cam/              # → Ability Cam/sessions.html（セッションの一覧、新しい順）
.venv/bin/python sessions.py Ability\ Cam/ --review     # 各記録の振り返りレポート（review.py）も作って、一覧からリンクする
.venv/bin/python review.py Ability\ Cam/ability-cam-20261026-140312.jsonl   # 1回分だけ
```
- 一覧：開始、長さ、顔が映っていた割合、横を向きすぎていなかった時間、変化の区間の数（アプリの画面に「いつもとの違い」が出始めた回数）、家族の印・場面の数、記録のファイル、備考（次に開いたときに整理したもの）
- **要約のない記録**：フォルダにあるのに `sessions.jsonl` に要約が無いファイル（アプリで次に開く前に写した、など）は、アプリと同じ数え方でここで要約して別の欄に出す
- `review.py` に `sessions.jsonl` を渡すと、`sessions.py` を使うよう案内して終わる

## 映り方チェック（`framing.py`、過去のファイル用）
アプリの「映り方チェック」は v0.4 でなくした（開いている間はいつも記録するため）。過去に残った `framing-checks.jsonl` はこれで読める。

`framing-checks.jsonl`（要約だけ）から、チェックごとの一覧と、顔が映っていた割合の比較の表を出す。numpy などは使わない。
```sh
.venv/bin/python framing.py framing-checks.jsonl                    # → framing-checks.html
.venv/bin/python framing.py 端末A/framing-checks.jsonl 端末B/framing-checks.jsonl --out 比較.html
```
- **映っていた割合の比較（メモごと）**：同じメモのチェックをまとめ、時間で重み付けした「顔が映っていた」「横を向きすぎていなかった（左右35°未満）」の割合
- **比較（チェックごと）**：割合の高い順。10秒ごとの、顔が映っていた割合を小さな棒で並べる
- **チェックの一覧**：時刻順。計測した時間、顔が映っていた時間、映らなかった時間の一番長い続き、解析コマ/秒、撮影→網目の遅れ、終え方、メモ

## 基準（`criteria.json`）
基準は `criteria.json` に置く。**変えたら `version` を更新し、`changelog` に日付と理由を1件足す。**
レポートの先頭と CSV のヘッダには、その回に使った基準（引数で変えた値も）が必ず出る。

| 指標 | 初期値 | 根拠 |
|---|---|---|
| 表情（mouth_smile, brow_down, eye_squint, jaw_open） | ならし 0.3秒、\|z\|≥2 が 0.5秒以上で開始 | ふつうの表情は 0.5〜4秒。0.5秒未満は微表情として「短い動き」に別に数える |
| 声（rms_db, f0_hz） | ならし 0.3秒、\|z\|≥2 が 0.5秒以上で開始 | 決まった根拠がない。`--calm` の記録で区間が多すぎないかを見て後から決める |
| 終了（すべて） | \|z\|<1.5 が 0.5秒続いたら | ヒステリシス（2 と 1.5 の間ではちらつかない） |

- **表情の「いつもより弱い」**（mouth_smile, brow_down, eye_squint, jaw_open が普段より下に外れた区間）は、アプリ（表情は「いつもより強い」だけを違いとして出す）と揃えて、
  区間の数・通知候補・`--calm` の10分あたり・印との対応には数えない。レポートの「表情の弱い方への変化（参考）」の欄に別に出し、CSV には `区分` が「参考（表情の弱い方）」の行として入れる。
  `criteria.json` の `face_below_counts` を `true` にすると、今までどおり区間に数える（2026-10-27 から。理由は `../docs/validation-log.md`）
- std の下限：表情 0.03、声の大きさ 6dB、声の高さ 10Hz（`criteria.json` の `std_floor`）。声の大きさの 6dB は 2026-10-27 から（静かな部屋で普段を取ったときに、小さな物音で区間にならないように）。アプリも v1.0 で揃えた。普段で `insufficient` の指標は計算しない
- **目を細める（eye_squint）からまばたきを外す**（2026-10-27 から。アプリも v1.0 で揃えた）：まばたき（eyeBlinkLeft/Right の平均）が `threshold`（0.3）以上のコマと、その前後 `pad_s`（0.2秒）は、
  eye_squint の値を使わず「判定対象外」にする（ならしにも入れない）。普段にも数えない：`--baseline-s` で作り直すときは外して数え、記録の baseline 行（アプリ）を使うときは、
  その普段を集めた時間（`started_ms`〜`t_ms`）のコマからアプリと同じ条件で eye_squint だけ数え直す（アプリの値はレポートの普段の表に並べて出す）。v1.0 からのアプリの baseline 行は `blink_masked: true` で、はじめから外してあるので数え直さない。
  `criteria.json` の `metrics.eye_squint.blink_mask: {threshold, pad_s}` で変えられる（消すと外さない）。記録の質に、まばたきで判定対象外だった時間を出し、z の時系列でも灰色に塗る
- 表情は、直近1秒で顔が映っているコマが半分以上、かつ |yaw| < 35°（v0.3 以降の記録）のときだけ判定する。それ以外は「判定対象外」
- 「普段を取り直す」から次の baseline 行までは、アプリと同じく判定しない
- 判定できない時間の直後に |z|≥2 のまま始まったものは、始まりが見えていないので「短い動き」に数えない（区間になったら備考に書く）
- `eda_response_window_s`（出来事の1〜4秒後）は、将来の手首の記録（皮膚電気活動）用。今は使っていない

## レポートの中身
- **使った基準**と変更の履歴
- **記録の質**：長さ、顔が映っていた割合、表情の判定対象外だった時間の割合、yaw の分布、解析コマ/秒、撮影→結果の遅れ（中央値・95%）。
  研究用の合計と指標に使っている表情の数値のうち、記録全体で最大値が 0.01 未満のもの（いつも0）は「この記録では値が出ていません（MediaPipe が出していない可能性）」として一覧に出す
- **カメラ**：先頭に、記録に使ったカメラ（ヘッダの `camera`、途中で切り替えたら `camera` の event も）。超広角のときは「画角の端では顔が歪み、表情の数値が変わることがある」と注意を出す。カメラが書かれていない記録（v0.8 より前）は広角
- **顔の向き**：正面・右・左・見えない・斜め の時間と割合（アプリと同じ決まりで、1コマごとの yaw から数え直したもの：正面 \|yaw\|<15°、横 >35°、その間は前の向きを続け、0.5秒続いたら変わり始めた時刻から数える。コマの間が1秒より空いたら数え直す）と、記録に書かれた `head_turn` の一覧（時刻・記録・前の向き）。z の時系列の一番上にも、同じ色で顔の向きの段を出す
- **普段**：v1.2 からの記録は、保存した普段（`source: "saved"`）で比べた日に今日の普段も `compared: false` で書かれる。区間はアプリと同じく、比べるのに使った行（`compared` が false でないもの）だけで判定する。普段の欄に、どの行がどちらの普段で、比べるのに使ったかを表で出す
- **保存した普段と今日の普段**（`--compare-saved` のとき）：記録の中の最初の保存した普段の行と、最初の今日の普段の行で、指標ごとの平均のずれ（（保存 − 今日）÷ 今日の標準偏差。標準偏差には下限をかける）と、
  同じ記録をそれぞれの普段だけで判定し直した区間の数（指標ごと・合計）を並べる。保存した普段は記録の始めから、今日の普段は記録し終えた時刻から判定する。どちらかの行が無ければ、そう書く
- **普段の長さの比べ**（`--compare-baseline` のとき）：普段ごとの、記録し終えた時刻・判定した時間・区間と短い動きの数・指標ごとの区間の数（`--calm` なら10分あたりも）
- **普段**：baseline 行ごとの、普段の長さ（`target_s`）、、集めるのにかかった時間（`wall_s`）と数えた時間（`valid_s`）・数えた条件、n / mean / std。v0.3 までの記録は `duration_s`（時計の時間）を「かかった時間」として出す
- **区間の数**：指標ごとの区間と短い動き。`--calm` のときは 1分あたり・10分あたりを出す（数字だけ。前にあった「10分に1回以下」の目安は根拠のない仮の値だったので、2026-10-27 に比べる表示をやめた）
- **印との対応**：家族の印ごとに、一番近い区間までの時間差
- **z の時系列**：指標ごと。±開始の z の線、いつもの範囲（薄い青灰の帯）、区間（アンバー＝いつもより上、青灰＝下）、場面（上の帯）、印（縦線）、判定対象外（灰色）。横軸は日本時間
  - 手首の記録（ability-lab.raw.v1）は、`review.py` の `Track` を足せば同じ時間軸に並ぶ作り（今は未実装）
- **通知候補（実際には通知しない）**：A＝表情と声が同時に区間に入って15秒以上、B＝同じ指標の区間が60秒以上、C＝30分以内に同じ指標の区間が3回以上。
  秒数・回数は `criteria.json` の `notify` で変えられる（すべて仮の値）。1時間あたりの件数を出し、場面が「食事・姿勢を変える・入浴・着替え」の間の候補は別の欄に分けて数える
- **表情の弱い方への変化（参考）**：`face_below_counts: false` のとき、表情の「いつもより弱い」区間を区間の一覧と同じ形で出す（区間の数の表と、普段の長さの比べの表にも、件数を別の列で出す）
- **研究用：上半分の顔の動きの合計（PSPI 型・研究用）**：区間の判定・通知候補には使わない。アプリ・見る側の画面には出さない（家族には見せない）。家族の印と照らし合わせて意味があるかを確かめるためのもの
  - 1コマごとに、普段からの差（今の値 − 普段の平均。マイナスは 0）で、browDown ＋ max(cheekSquint, eyeSquint)（どれも左右平均。eyeSquint はまばたきのコマを除く）
    ＋ 目を閉じている間の eyeBlink（左右平均が 0.5 以上の状態が 0.5秒以上続いたまとまり全体。短いまばたきは入れない）を、重みを付けずに足す（根拠のない重みは使わない）
  - noseSneer・mouthUpperUp（AU9/10）は 2026-10-27 に外した：MediaPipe では noseSneer がずっと 0 で、mouthUpperUp は声を出す・口を開ける動きで上がったため。cheekSquint（AU6）もずっと 0 だが、max の中なので残している
  - 普段の平均は、記録の baseline 行の時間（`started_ms`〜`t_ms`）のコマから、アプリと同じ条件（普段に数えるコマ・3コマに1コマ）で数え直す（`--baseline-s` のときは作り直した普段の時間）。サンプルが30未満の値は使わず、そのコマは計算しない
  - 表情の判定対象外の時間（顔が読めない・横向き）と、普段が無い時間は計算しない
  - 時系列のグラフ（0.3秒でならしたもの）に、家族の印（紫の縦線）と場面（上の帯と点線）を重ねる
  - 家族の印があれば、印ごとの前後30秒の平均と、印の値（快／不快／分からない）ごとの平均を、印のない時間（どの印の前後30秒にも入らないコマ）の平均と並べる。印が10件たまるまでは「数が少ない」と出す
  - `criteria.json` の `research_composite`（`groups`・`eye_closed`・`smooth_s`・`mark_window_s`・`min_marks`・`enabled`）で変えられる
- **区間の一覧**：開始・終了（日本時間）、長さ、指標、向き（いつもより強い／弱い・大きい／小さい・高い／低い）、ピークの z、普段の平均 → ピークの値、場面、前後10秒の印、顔が映っていた割合、yaw の平均

## テスト
```sh
.venv/bin/python tests/make_fixture.py               # 作り物のテスト用記録を作り直す
.venv/bin/python -m unittest discover -s tests
```
`test_sessions.py` は、記録のファイルからの要約（空きの切り方・横向き・区間・印・場面・壊れた最後の行）と、一覧の HTML を確かめる。
`test_framing.py` は映り方チェックの読み込み（メモは一番新しいもの・同じ要約は1つ）、メモごとのまとめ、HTML を確かめる。
`CompositeTest` は、研究用の合計（普段からの差・マイナスは 0・グループの中の最大・目を閉じている間だけ eyeBlink・判定対象外は計算しない）、印の前後との比べ、区間の判定に使っていないことを確かめる。
`BlinkAndVoiceFloorTest` は、まばたきのコマと前後0.2秒が外れること、外すと目を細めるの区間にならないこと、普段からも外れること（アプリの値は残す）、声の大きさの下限 6dB を確かめる。
`FaceBelowTest` は、表情の「いつもより弱い」が初めは区間・10分あたりに入らず参考の欄に出ること、`face_below_counts: true` なら区間に入ることを確かめる。
`tests/fixture_basic.jsonl` は人の記録ではなく、区間・短い動き・ヒステリシス・判定対象外・取り直し・顔の向き（`head_turn`）を確かめるための作り物。
`test_review.py` の `HeadTurnTest` は、顔の向きの決まり（0.5秒・15°/35° のヒステリシス・見えなくなる直前の角度・斜め）と、記録に書いた `head_turn` を1コマごとの向きから数え直すと同じになることを確かめる（アプリの `HeadTurnTracker` を変えたら `review.head_states` も同じに変える）。
