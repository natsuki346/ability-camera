# 話者の区別（だれの声か）の計画

2026-10-28、v1.9.4 の時点での調べと計画。**まだ実装していない**（コードは変えていない）。
文言は [`wording-guide.md`](wording-guide.md) に従う。試したことは [`validation-log.md`](validation-log.md) に残す。

## 目的と決まり

- **目的**：だれが話しているか（本人／家族それぞれ）を分け、それぞれの人の声のあとに、本人の表情・声がどう変わったかを事実として記録する。
  例「家族 A の声（13:42:05〜、4秒）のあと 10秒：眉を寄せる動きが、いつもより強い（3秒）」。気持ち・状態の名前は付けない
- **本人確認・認証には使わない**（鍵を開ける・本人と決めて何かを許す、のようなことには使わない）
- 端末の中でその場で計算する。映像・音声は保存も送信もしない
- 声の特徴の数値（埋め込み）は、端末の `persons.json` の中だけに置く。記録（JSONL）には、だれの声か・似ている度合い・使ったモデルの版だけを書き、埋め込みそのものは書かない。見る側にも送らない
- 人ごとの声の登録は、今の「声の普段」と同じ流れで作る（その人の声が○秒たまったら作る。取り直せる。途中まで集めた分の扱い・14日で捨てる・取り直し中は古い登録を残す、も同じ）
- 今の本人の声の見分け（声の高さの範囲＋口の動き、`voice_self`）は残し、同じ記録の中で両方の判定を書く（あとで比べるため）

## 1. iPhone でその場で動く話者の埋め込みモデルの候補

どれも 16kHz・1チャンネルの声から、決まった長さの数値（埋め込み）を出す。2つの埋め込みの似ている度合い（コサイン類似度）で同じ人かを見る。

| 候補 | 大きさ | 1回の計算時間の目安 | 必要な声の長さ | ライセンス | Core ML |
|---|---|---|---|---|---|
| **A. WeSpeaker ResNet34-LM**（pyannote の `wespeaker-voxceleb-resnet34-LM`。FluidAudio が Core ML に変換して公開） | 約 660万パラメータ（約 26MB、fp16 で約 13MB）※1 | Neural Engine で数 ms〜十数 ms と見込む（**要測定**） | 1.5〜3秒（LM は 3秒より長い声で良くなる） | 重みは CC BY 4.0（VoxCeleb に従う：表記が要る）。変換済みのものは FluidAudio の配布条件も確かめる | 変換済みがある（`FluidInference/speaker-diarization-coreml` の legacy `wespeaker`・`wespeaker_int8`） |
| **B. CAM++**（3D-Speaker、Alibaba） | 約 720万パラメータ・1.73 GFLOPs（約 29MB、fp16 で約 15MB） | ECAPA-TDNN より軽く速い（論文）。Neural Engine で数 ms と見込む（**要測定**） | 1.5〜3秒 | ツールキットは Apache-2.0。重み（VoxCeleb・3D-Speaker で学習）の条件は **ModelScope のモデルページで要確認** | 変換済みは見つからなかった。PyTorch を trace して coremltools で ML Program にする（fbank はアプリ側で計算、入力の長さは固定にする） |
| C. ReDimNet2-B6（変換済み Core ML） | 約 1230万パラメータ・28.6MiB | M5 Pro で 1回 約 13.6ms（6秒の声）。iPhone はこれより遅い | **6秒に固定** | 変換したものは MIT。元の重みの条件は書かれていない（要確認） | 変換済みがある（iOS 18〜） |

（参考：SpeechBrain の ECAPA-TDNN は Apache-2.0・VoxCeleb1 で EER 0.80% だが、約 2000万パラメータで大きいので候補から外した。NVIDIA TitaNet-Small は約 600万パラメータ・EER 1.08% だが、NeMo の条件で Core ML への変換の例も見つからないので外した。）

※1 パラメータ数は WeSpeaker の ResNet34 の一般的な値。pyannote のモデルカードには書かれていないので、変換済みのファイルで確かめる。

**勧め：まず A（WeSpeaker ResNet34-LM の変換済み Core ML）で試し、計算が重い・登録に声が足りない、なら B（CAM++）を変換して比べる。**
- A は iOS で動いている変換済みのものがあり、変換の手間と失敗の心配が少ない。介助の場面の短い発話（1〜3秒）に合う
- B は軽さ・精度の数字が良いが、変換と重みの条件の確認が要る
- C は 6秒の固定長で、言葉を交わす場面（1発話が短い）には長すぎる
- どれも英語中心の VoxCeleb で学習している。日本語の家庭の声・小さな声・声を出しにくい人の声でどれくらい分けられるかは分からないので、下の「4. 試し方」で確かめてから使う

## 2. 今の音の流れのどこに入れるか、29〜30コマ/秒と撮影→結果 約43ms を保てるか

今の流れ：`AVAudioEngine` の入力のタップ（48kHz、約0.1秒の塊）→ `AudioAnalyzer.analyze`（音量・声の高さ）と `blocks`（映像のコマごとの音量、`type: "audio"`）。
表情は `CameraManager` → `FaceAnalyzer`（MediaPipe）で、音とは別のスレッド。

入れる所：
1. **タップの中では計算しない**（音が途切れないように）。タップの中では、塊を 16kHz に変換（`AVAudioConverter`）して、約3秒の輪になったバッファ（メモリだけ。ファイルにしない）に足すだけ
2. **別の低い優先度のキュー**（`DispatchQueue(qos: .utility)`）で、**声が出ている間だけ**、約0.5秒ごとに直近 1.5秒（足りなければ取れた分）の埋め込みを1つ求める。Core ML は `computeUnits = .cpuAndNeuralEngine` にして、MediaPipe（GPU・CPU）とぶつかりにくくする
3. 埋め込みを、登録した人（本人・家族それぞれ）の登録の埋め込みと比べ、いちばん似ている人・似ている度合い・2番目との差を出す。結果だけを記録に書き、埋め込みと 16kHz の声はすぐ捨てる（輪のバッファも上書きされる）

29〜30コマ/秒と約43ms を保てるか：
- 見込みでは保てる。計算は 0.5秒に1回・1回数 ms〜十数 ms で、表情の解析とは別のキュー・別の計算資源（Neural Engine）で動かすため。**ただし測るまでは分からない**
- 確かめ方：「数字」のページに「話者の計算 ms」「話者の計算の回数/秒」を足し、話者の区別をオン／オフにして、解析コマ/秒・撮影→結果・撮影→網目を比べる（同じ端末・同じ場面で各2分）
- 守れなかったときの順番：(1) 計算の間隔を 1秒にする、(2) int8 のモデル（A は変換済みがある）、(3) 声が出ていて**本人の顔の口が動いていない**とき（ほかの人の声の候補）だけ計算する、(4) それでも落ちるなら端末を限る
- 熱・電池：30分の記録で、端末の温度の状態（`ProcessInfo.thermalState`）と電池の減りを、オン／オフで比べる

## 3. 登録・判定・記録の形

### 登録（`persons.json` の中だけ）
- 人の一覧に、本人のほか家族も入れられるようにする（人ごとに「本人として撮る人」か「家族」かを持つ。名前は今まで通り端末の中だけ）
- 人ごとに `speaker`（声の登録）：`{ "model": "wespeaker-r34lm-coreml-v1", "dim": 256, "embedding": [...], "n": 20, "valid_s": 30.0, "saved_ms": ..., "spread": 0.12 }`
  - `embedding` は登録に使った声のまとまり（1.5秒ごと）の埋め込みを長さ1にそろえて平均したもの。`spread` は、そのまとまりどうしの似ている度合いのばらつき（大きすぎたら「声の登録のばらつきが大きいです（取り直せます）」）
  - **登録の流れは「声の普段」と同じ**：本人なら本人の声のコマ（`voice_self: true`）が合計 30秒（仮）たまったら作る。家族は、設定の「人」で「声を登録する」を押して、その人がひとりで話している間に集める（ほかの人の声が混ざらないように、画面に「〇〇の声を集めています（12/30秒）」と出し、止められる）
  - 途中まで集めた分は、今の `voice_partial` と同じく人ごとに残し、14日で捨てる。取り直しは、たまって保存し直すまで古い登録を残す
  - `persons.json` は今 `completeFileProtection` で書いているが、iCloud のバックアップに入る場所にある。**埋め込みを入れる前に `isExcludedFromBackup` を付けて、バックアップに入れない**ようにする
- モデルを替えたら、前のモデルの登録は使わない（`model` が違えば比べない）。取り直しを出す

### 判定
- 声が出ている間、約0.5秒ごとに：いちばん似ている人の似ている度合い `score` が しきい値（仮 0.5）以上、かつ 2番目との差 `margin` が（仮 0.1）以上なら、その人の声。そうでなければ「分からない」
- 1回ずつだとちらつくので、同じ人が 2回続いたら決める（約1秒）。決めたものを「だれの声の区間」にする（0.5秒以上の切れ目でひとまとまり。`voice_on` と同じ決まり）
- 今の本人の声の見分け（`voice_self`）はそのまま。**話者の区別で `voice_self` を変えない**（同じ記録に両方を書いて、あとで比べる）

### 記録（JSONL）に足すもの
- ヘッダ：`speaker_model`（例 `"wespeaker-r34lm-coreml-v1"`）、`speaker_enrolled`（登録した人の id と、本人として撮る人かどうか：`[{"id": "...", "role": "self"}, {"id": "...", "role": "family"}]`。名前・埋め込みは書かない）、`speaker_threshold`・`speaker_margin`
- 新しい行 `type: "speaker"`（約0.5秒ごと、声が出ている間だけ）：

  | キー | 意味 |
  |---|---|
  | `t_ms` | 埋め込みを求めた声のまとまりの終わりの時刻 |
  | `window_ms` | 使った声の長さ（1500 など） |
  | `scores` | 登録した人ごとの似ている度合い `{ "<id>": 0.71, "<id>": 0.32 }`（埋め込みではない） |
  | `speaker` | そのまとまりの判定：人の id / `"unknown"` |
  | `model` | 使ったモデルの版（ヘッダと同じ。途中で替わらない） |
  | `calc_ms` | 計算にかかった時間 |

- `event`（`kind: "speaker"`）：だれの声の区間が始まった・終わった（`speaker`・`from`）。今の `head_turn` と同じく、決まった時刻を書く
- 書かないもの：埋め込み・声そのもの・名前

### review.py・check_app.py で再現できるか
- 声を保存しないので、**埋め込みと `scores` を求めるところはレポートでは再現できない**（アプリが書いた `scores` を読むだけ）
- その先（`scores` からの判定：しきい値・差・2回続いたら決める・区間にまとめる）は、アプリと同じ決まりを `review.py` に置き、`check_app.py` でアプリ（DiffCheck に話者の判定を足す）と区間が一致するかを確かめられる。今の `voice_on` と同じやり方
- しきい値を変えたらどうなるかは、記録の `scores` から試せる（`voice_check.py` に「話者の判定」の列を足す）
- レポートに出すもの：だれの声の区間の一覧と長さ、人ごとの声のあと 10秒（仮）の本人の表情・声の違い・目を閉じている・顔の向きの分布（今の「家族の印の前後」と同じ形）、`voice_self` と話者の判定が食い違ったコマの割合

## 4. 2人（自分＋もう1人）で、今の方法と比べる試し方

1. **登録**：前面カメラで自分を映し、自分の声を 30秒（読み上げと普段の話し方）。もう1人は設定の「人」から、ひとりで 30秒話して登録する（静かな部屋で）
2. **台本のある記録（約5分）**：前面カメラは自分に向ける。次を順に行い、時刻を声で言わずに場面のボタン（「その他」）で区切る
   - 自分だけ話す 30秒／もう1人だけ話す 30秒（自分は黙って小さくうなずく・口を少し動かす：20:25 の記録で困った場面）
   - 交互に 5秒ずつ 1分／2人が重ねて話す 20秒／もう1人がささやく・自分が小さな声 各20秒
   - テレビの声だけ 20秒（登録していない声）／黙っている 30秒
3. **正解**：場面の区切りと、あとで自分たちで付けた「だれが話していたか」の時間（`voice_check.py --self … --other …` と同じ形）
4. **比べるもの**（`voice_check.py` に話者の判定を足して、同じ表に並べる）：

   | 決まり | 本人の声を本人と言えた | ほかの人の声を本人と言ってしまった | もう1人の声をもう1人と言えた | テレビの声を「分からない」にできた |
   |---|---|---|---|---|
   | 今（声の高さの範囲＋口の動き） | | | –（分けられない） | – |
   | 話者の区別だけ | | | | |
   | 両方（話者の区別が本人で、かつ今の決まりも本人） | | | | |

5. **場所を変える**：同じ台本を、胸に着けた背面カメラ（介助する人の胸）でも行う。マイクと口の距離が変わると似ている度合いが変わるので、登録した場所（前面・静かな部屋）と使う場所が違うときにどれくらい下がるかを見る
6. **数字の確かめ**：話者の区別のオン／オフで、解析コマ/秒・撮影→結果・話者の計算 ms・端末の温度
7. 結果と決めたこと（しきい値・登録の秒数・使うかどうか）を `validation-log.md` に書く。**本人の声を本人と言えた割合が今の方法より下がるなら、話者の区別は記録とレポートだけにして、画面には出さない**

## 5. README の原則の書き換え案

今（README の「本人の声の見分け」）：「**声紋（声の特徴で人を特定するもの）は作らない**」、「人ごとの普段」：「顔認証はしない」。

案（README の「原則」に1つ足し、上の2か所はこれを指すようにする）：

> - **顔認証はしない。声の特徴は、だれの声かを分けて記録するためだけに使い、本人確認・認証には使わない**（v2.0〜の予定、`docs/speaker-plan.md`）。
>   - 声の特徴の数値（埋め込み）は、登録した人が同意したときだけ作り、この端末の `persons.json` の中だけに置く（バックアップにも入れない）。記録（JSONL）・見る側・ほかの端末には送らない。記録には、だれの声か（人の id）・似ている度合い・使ったモデルの版だけを書く
>   - 人ごとに、設定の「人」でいつでも消せる・取り直せる。人を消すと声の登録も消える
>   - 声そのもの・映像は今まで通り保存しない。計算は端末の中でその場で行う
>   - 画面と記録の言い方は「家族 A の声（4秒）」「だれの声か分からない声」のように事実だけにし、「〇〇さんと判定」「本人と確認」とは言わない（`docs/wording-guide.md`）

あわせて `wording-guide.md` に足す案：「だれの声か」は「〇〇の声（4秒）」「だれの声か分からない声」だけ。「話しかけた」「呼んだ」「〇〇さんと判定」「声紋」とは書かない。似ている度合いは記録の質としてだけ数字で出す（画面には出さない）。

## 実装の順番（案）

1. 候補 A の変換済み Core ML をアプリに入れ、「数字」のページに計算時間だけを出す（判定も記録もしない）→ 29〜30コマ/秒・約43ms が保てるか
2. 本人の声の登録（今の声の普段と同じ流れ）と `type: "speaker"` の行・ヘッダ。`review.py` は読むだけ
3. 家族の登録、判定の決まりを `criteria.json`・アプリ・`review.py` に置き、`check_app.py` で区間の一致
4. 2人の試し（上の 4）→ しきい値を決める → レポートに「人ごとの声のあとの本人の変化」
5. 画面に出すかは、記録を見てから決める（出すなら「家族 A の声」と小さく）
