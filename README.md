# Ability Cam

介助者の胸に留めたスマホの背面カメラとマイクで、表情と声の変化をその場で解析する検証用アプリ。

## 確かめたいこと（根本の仮説）
- 映像から表情の変化を、音声の大きさ・高さから状態の変化を、読み取れるか
- それを即時に（撮影→結果の遅れが小さく）出せるか

画面に出る合格の目安：顔が映っている割合 / 解析コマ/秒 / 解析時間 / 撮影→結果の遅れ

## 原則
文言と色のルールは [`docs/wording-guide.md`](docs/wording-guide.md) が正。画面とレポートはこれに従う。

実際に試したこと・結果・分かったこと・決めたことは、日付ごとに [`docs/validation-log.md`](docs/validation-log.md) に残す。

- 映像と音声は保存しない。外にも送らない（端末の中でその場で解析する）
- **顔認証はしない。声の特徴は、だれの声かを分けて記録するためだけに使い、本人確認・認証には使わない**（v1.10〜、`docs/speaker-plan.md`）。
  - 声の特徴の数値（埋め込み）は、登録した人が同意したときだけ作り（だれが同意したかを `persons.json` に残す）、この端末の `persons.json` の中だけに置く（バックアップにも入れない）。
    記録（JSONL）・見る側・ほかの端末には送らない。記録には、だれの声か分けるための似ている度合い（人の id ごと）・使った声の長さ・計算時間・使ったモデルの版だけを書く
  - 人ごとに、設定の「人」でいつでも消せる・取り直せる。人を消すと声の登録も消える
  - 声そのもの・映像は今まで通り保存しない。計算は端末の中でその場で行う
  - 画面と記録の言い方は「家族 A の声（4秒）」「だれの声か分からない声」のように事実だけにし、「〇〇さんと判定」「本人と確認」とは言わない（`docs/wording-guide.md`）。v1.10 では画面には何も出さない
- 振り返りレポートには、研究用に「上半分の顔の動きの合計（PSPI 型・研究用）」も出す。区間の判定・通知候補には使わず、アプリ・見る側の画面には出さない（家族の印と照らし合わせて意味があるかを確かめるため。`analysis/README.md`）
- 判定の基準は、まず振り返りレポート（`analysis/criteria.json`）で試し、何もしない記録で効果を確かめてからアプリに揃える。v1.0 でアプリ（撮る側・リプレイ）をレポートの基準に揃えた（`ios/AbilityCam/DiffEngine.swift`。値を変えるときは `criteria.json` と両方変える）
- 記録（JSONL）にも、動画ファイルにも、リポジトリには入れない（`.gitignore` 済み）
- 医療機器にはしない。「気持ちが分かる」「痛みを検知」とは言わない

## 構成
- `ios/` … iOS アプリ（SwiftUI + MediaPipe Face Landmarker + AVAudioEngine）
- `web/` … ブラウザ版（録画ファイルの解析にも使える）
- `analysis/` … PC 用の振り返りレポート（記録から、普段から外れた区間を出す `review.py`、これまでの記録の一覧 `sessions.py`）。使い方は `analysis/README.md`

## iOS のビルド（Mac）
```sh
brew install xcodegen cocoapods
cd ios
TEAM_ID=あなたのチームID ./setup.sh   # 古い複製をゴミ箱へ → モデルの取得 → xcodegen → ワークスペースを作り直して pod install → 確かめる
open AbilityCam.xcworkspace           # .xcodeproj ではなくこちらを開く
```
iPhone をつないで実行。初回は、iPhone の 設定 > 一般 > VPNとデバイス管理 で開発元を信頼する。

`setup.sh` は何度動かしてもよい（v1.6.3〜）。
- `ios/` に「AbilityCam 2.xcodeproj」のような古い複製（名前に空白と数字が付いたもの）があれば、名前を出してゴミ箱（`~/.Trash`）に移す。
- `AbilityCam.xcworkspace` は消してから作り直し、参照が `AbilityCam.xcodeproj` と `Pods/Pods.xcodeproj` の2つだけかを確かめる（違えばエラーで止まる）。
- 2回目からは `TEAM_ID` を省くと、前に作ったプロジェクトのチームIDを使う。
- 使うプロジェクトは `Podfile` の `project 'AbilityCam.xcodeproj'` で決めてある。

**「Cannot find 'PitchTracker' in scope」のように「Cannot find 〜 in scope」でビルドが失敗したとき**は、Xcode が古いプロジェクトを開いていて、新しいファイルが入っていない。次の順で直す。
1. Xcode を ⌘Q で閉じる
2. `cd ios && ./setup.sh`
3. `open AbilityCam.xcworkspace` で開き直す
4. ⇧⌘K（Product > Clean Build Folder）してからビルドする

## 役割と通信（v0.5〜v0.8）
同じアプリに2つの役割がある。最初の画面で選び、次からは覚えておく（右上の歯車の設定で変えられる。撮る側から見る側に変えると、今の記録を閉じて整理する）。

| 役割 | 端末 | すること |
|---|---|---|
| **撮る側** | iPhone（胸に着ける） | 下の「画面」のとおり。解析・記録はこちらだけ |
| **見る側** | iPad。Apple シリコンの Mac では iPad 用アプリとして動かす（Mac 専用アプリは作らない） | 撮る側の顔の絵・いつもとの違い・記録の状態をその場で見る。**何も保存しない** |

- **通信**：MultipeerConnectivity で端末どうし直接つなぐ（同じ Wi‑Fi か Bluetooth の届く所）。インターネット・クラウドは使わない。暗号化は必須（`encryptionPreference: .required`）。サービス名 `abilitycam`（Info.plist の `NSBonjourServices` に `_abilitycam._tcp` / `_abilitycam._udp`、`NSLocalNetworkUsageDescription` あり）
- **つなぎ方（v0.6）**：見る側は起動したら自動で撮る側を探して申し込み、切れたら自動でつなぎ直す（撮る側が前に戻ったときも）。
  初めての端末は、撮る側の画面に「〇〇に状態を送りますか？」と出て、「送る」を選んだときだけつなぐ。「送る」を選ぶと撮る側はその端末を覚え、暗号化されたつながりの上で合言葉（ランダムな24バイト）を渡す。次からは、見る側が申し込みにその合言葉を付けると確認なしでつなぐ（名前だけでは通らない）。
  撮る側の設定「許可した端末」に一覧があり、1台ずつ取り消せる（つながっていれば切る）。確認なしでつないだときも、撮る側の上の帯に「〇〇が見ています」が必ず出る。
  - **合言葉を忘れるのは、撮る側がはっきり断ったときだけ（v0.6.1）**：見る側の合言葉が合わない（取り消した・撮る側が知らない）とき、撮る側は確認を出さずに「取り消されています」と理由を付けて断る
    （申し込みの断り方には理由を付けられないので、伝えるだけのつながりを受けて `revoked` を送り、2秒で切る。このつながりは見ている端末に数えず、状態も送らない）。
    見る側はこの返事を受け取ったときだけ合言葉を忘れ、「〇〇で許可が取り消されています」と出す。自動では申し込まない（介助中の撮る側に確認を出さないため）。もう一度見るには、見る側で「見たいと申し込む」を押し、撮る側で確かめる
  - **それ以外でつながらなかったとき**（電波が悪い・時間切れ・撮る側が見つからない・撮る側が裏に回っている・つながっていたのが切れた）：合言葉は持ったまま、2秒・4秒・8秒・16秒・30秒…（最大30秒）と間をあけてつなぎ直す。
    撮る側が見つかった（前に戻った）ときは待たずにすぐつなぐ。見る側には「〇〇とつなぎ直し中（〇秒後にもう一度）」と出る
  「送らない」を選んだ撮る側や「切る」で切られた撮る側には、見る側を開き直すまで自動では申し込まない（見る側の「見たいと申し込む」で手で申し込める）
- **撮る側の画面**：見ている端末があるあいだ、上に「〇〇が見ています」と出る。「切る」でその端末だけ切る（見る端末ごとにセッションを分けている）。名前は設定の「この端末の名前」（空なら端末の名前）
- **送るもの**（1秒に10回まで。前の送信が終わっていなければその回は飛ばすので、解析のコマ/秒は落とさない）：撮影の時刻、顔が読めているか、顔の向き（yaw / pitch / roll）、顔の絵を動かすのに使っている表情の数値（ならした値）、各指標のそのコマの値（表情4つ・声の大きさと高さの数値。v0.6 の60秒のグラフ用に足したもので、v0.7 の見る側の画面では使っていない）、いつもとの違いの一覧（続いている秒数つき）、普段の記録の進み具合、記録中かと経過時間、今の場面、顔が映っている割合、解析コマ/秒。家族の印・場面のイベント。v1.11 から、記録している人の名前（`personName`。記録していないときは送らない）
  - v0.7 で足したもの：各指標の今の z（v1.0 からは 0.3秒でならした値から。比べられない指標は入れない）、違いごとの指標・向き・続いている秒数、このセッションで違いが出た回数（`sessions.jsonl` の `segments` と同じ数え方）
  - **顔の向きの記録（v0.8.1）**：記録に書いた `head_turn` と同じもの（時刻・`value`・新しい向き）を、このセッションの直近5件まで撮る側が覚えておき、
    1件増えるたびに一覧ごと送る（`head_turns`）。見る側がつながったとき（つなぎ直したときも）にも一覧を1回送るので、次の head_turn を待たずに直近のものが出る。新しいセッションを始めたとき・閉じたときは空の一覧を送る。
    記録していないときは記録に書かないので送らない
  - v0.8 で足したもの：顔の向き（`head`：正面／右／左／見えない／斜め。撮る側で0.5秒続いて決まったもの。下の「顔を向ける・そむける」）
  - **普段（v0.7）**：普段の記録が終わったとき（取り直したときも）に、各指標の `n` / 平均 / 標準偏差 / `insufficient`（`baseline` 行の `metrics` と同じもの）を1回送る。見る側がつながったときにも今の普段を1回送る。取り直し始めたときは「普段はまだ無い」を送り、見る側のいつもの範囲を消す
- **映像（初めはオフ）**：撮る側の設定「見る側に映像も送る」をオンにしたときだけ、長い辺 480px の JPEG を毎秒5コマまで送る。オンのあいだは撮る側の帯に「映像を送っています」が必ず出る。見る側は表示するだけで保存しない。
  映像を送っていないときの解析コマ/秒を覚えておき、送っていて1割より落ちたら送る間隔を広げる（最長2秒に1コマ。戻れば縮める）。JPEG にするのは別のスレッドで1コマずつ、前のコマの途中なら飛ばす
- **送らないもの**：音声、顔の478点の座標、JSONL などのファイル（映像はオフのあいだ送らない）
- **見る側の1画面（v0.7）**：「今の値が、その人のいつもの範囲のどこにあるか」と「何が・どちらに・どれだけ続いているか」を、少し離れた所からも読める大きさで出す。状態の名前や点数は出さない。
  Mac の全画面など横長（幅 1000pt 以上）では3列、iPad の縦では上から順に並ぶ。文字の大きさは画面の幅に合わせて変わる
  - 左の列：顔の絵（大きく）。映像を受け取っているときはその下に映像。その下に顔の向き（「顔の向き：右 25°・下 10°（本人から見て）」、横を向きすぎていれば「横を向いているため表情は参考程度」）
    - **顔の向きの記録（v0.8.1）**：その下に、直近の `head_turn`（「見えなくなった（直前は右 40°）」など）を大きな文字で出し、**次の head_turn が来るまで消さない**（つながっていない間も出したまま。全体は灰色になる）。
      左に時間の流れの「顔の向き」の段と同じ色の印、下に「13:42:05 から（1分12秒）」（撮る側の時計。届かなくなっても進める）。「見えなくなった」は少し大きく出す。
      その下に直近5件の一覧（新しい順、時刻つき）。別の撮る側につないだときは消す
  - 真ん中の列「いま」：指標ごとの横長のメーター6本（口角を上げる・眉を寄せる・目を細める・口を開ける・声の大きさ・声の高さ）。
    表情の4本の下に「目を閉じている」の1行（v1.4〜。メーターは無く、「閉じている（4秒）」／「閉じていない」だけ。撮る側が判定していないとき・古い撮る側からは空）。
    横軸は z（−5〜+5）で、いつもの範囲（普段の平均 ±2 標準偏差。標準偏差は撮る側と同じ下限をかける）を薄い青灰の帯、今の値を濃紺の点で示す。
    「いつもとの違い」に出ているときは点をアンバーにし、横に「いつもより強い（12秒）」と出す。メーターの下に、いつもの範囲と今の値を数値で小さく出す（表情は 0〜1、声は dB / Hz）。
    顔が読めないとき・普段を記録中のときは、表情のメーターを薄くして理由を出す（声のメーターは出したまま、普段を記録中なら「いつもの範囲はまだありません」）。
    その下に「いつもとの違い」の一覧を大きな文字で（続いている秒数つき）
  - 右の列：記録の状態（記録中・経過時間・普段の記録の進み具合）、つながり（最後に受け取った時刻・撮影→この画面 ms）、記録の質（顔が映っている割合・解析コマ/秒）、このセッションで違いが出た回数、直近の家族の印・場面の一覧（時刻つき、見る側で押したものは端末の名前つき）
  - 下の帯「時間の流れ」：表示する長さを 1分・5分・15分 から選ぶ（届いたものを見る側のメモリにだけ最長15分置く。保存しない。同じ撮る側につなぎ直したときは続け、別の撮る側なら消す）。
    指標ごとに1段ずつ、「いつもとの違い」に出ていた時間を塗る（アンバー＝いつもより上、青灰 `#5B7FA6`＝いつもより下）。いつもの範囲だった時間は薄い青灰、比べていない時間（記録していない・普段を記録中・顔が読めない・データ不足・値が無い）と届いていない時間は斜線。
    塗るのは撮る側の「いつもとの違い」と同じ決まりなので、表情は「いつもより強い」だけ（振り返りレポートの区間とは基準が違う）。場面は上の段の帯、家族の印は縦線（名前と時刻つき）。横軸は撮る側の時計の時刻で、右端が今
    - **目を閉じているの段（v1.4〜）**：表情4段と声2段の間に1段。閉じていた時間を墨紫 `#5E4B8B`、閉じていない時間を薄い青灰、判定していない・届いていない時間を斜線で塗る（撮る側が送る `eyes_closed`）
    - **顔の向きの段（v0.8）**：場面の下に1段。撮る側で決まった向きを、正面＝薄い青灰 `#DCE3EA`、右＝青灰 `#5B7FA6`、左＝砂色 `#B8A07A`、見えない＝灰 `#7D848C`、斜め＝薄い藤色 `#C9C4D9` で塗る（十分な幅があれば「正面」「右」などの文字も）。
      まだ決まっていない・届いていない・古い撮る側の間は斜線。撮る側は0.5秒続いたのを確かめてから送るので、見る側の塗りは記録の `t_ms`（なり始めた時刻）より約0.5秒遅れて始まる
  - その下：家族の印と場面のボタン
  - つながっていないとき・データが2秒以上来ないときは、全体を灰色にして「つながっていません（最後に受け取った時刻 hh:mm:ss）」を上に大きく出す（止まっているのを「違いがない」と見間違えないため）。メーターと時間の流れにも最後に受け取った時刻を出し、時間の流れは右端（今）を進め続けて、届いていない間を空けて見せる
- **見る側から印と場面を付ける（v0.6）**：見る側のボタンを押すと撮る側に送り、撮る側の JSONL に記録する（`event` に `"source": "viewer"`、押した端末の名前 `by`、`clock_corrected`）。時刻は見る側で押した瞬間を、2台の時計のずれを直して撮る側の時計で記録する（ずれをまだ測れていないときは直さずに記録し、`clock_corrected: false`）。
  撮る側の画面にも「〇〇が家族の印を付けました：不快（13:42:05）」と短く出す（wording-guide に合わせて「家族の印」と分かる形にしている）。記録中でないときは受け付けない
  「撮影→この画面 ms」は、2秒ごとに往復を測って2台の時計のずれを直した、撮影から届くまでの遅れ（往復が一番短かったときのずれを使う）

## 画面（v1.0）
- **撮る側（iPhone）の「いま」は、スクロールなしの1画面**（小さい iPhone の SE の高さでも、家族の印のボタンまで見える）
  - 上：左に ≡（サイドバーを開く）、真ん中に「記録中 12分34秒」と、その下に小さく記録している人（「姉」。v1.3 から「さん」は付けない。v1.11.2 からは、押すと「記録を終えますか？」だけを出す。人は記録中は変えない）、右に歯車（設定）。その下に「〇〇が見ています」「映像を送っています」の帯（出ているときだけ）
  - 真ん中：顔の絵（幅 140pt）と小さいカメラ映像（網目つき。タップで大きく、もう一度タップで戻る）を横に並べる。絵の下に顔の向き。
  - その下の空いている所は、**横にスワイプして切り替える3ページ**（下にページの点。v1.1〜）：
    1. **いま**（初めに出す）：大きく「いつもとの違い」を最大3行（例「眉を寄せる動きが、いつもより強い（12秒）」。多いときは「ほか2件」）。無いときは「いつもと大きな違いはありません」を同じ大きさで。
       その下に指標6本のメーター（見る側の「いま」と同じ描き方を小さくしたもの：いつもの範囲の帯と今の点、外れたらアンバー）。v1.2 から縦1列6本にし、空いている高さに合わせて太くなる。
       顔が読めないときに薄くするのは表情の4本だけ（声の2本は普通の濃さ）。ダークモードでは、濃紺の文字と進み具合のバーを明るい青灰にする（ライトモードは濃紺のまま）。
       保存した普段で比べているときは、状態の表示は「顔：読めています・普段：保存した普段（10/28 15:10）」だけ（うしろで記録している今日の普段は、進み具合も含めて出さない、v1.3〜）。
       上に状態の小さな表示（「顔：読めています／読めません」「普段：記録中 12/30秒／記録しました」）。「普段を取り直す」はこのページの右上。普段を画面に出して記録している間は進み具合
    2. **グラフ**：直近の指標ごとの z の線（表示する長さ 20秒・1分・5分。この端末のメモリにだけ最長5分置き、保存しない）。いつもの範囲（±2）を薄い帯、家族の印を濃紺の点線、場面を灰の点線で。
       指でグラフをなぞると縦線がついてきて、その時刻の「何秒前」と、指標ごとのならした値・いつもの範囲を上に出す（例「12秒前」「眉を寄せる 0.32（0.00〜0.10）」）。なぞっている間はグラフを止め、指を離すと今に戻って流れ始める。
       目を閉じていた時間（v1.4〜）は、上から下までの墨紫の薄い帯で出す（なぞった時刻が閉じていた間なら「目を閉じていた」と出す）。
       z は判定に使ったもの（まばたきを待つ分、約0.2秒前のコマ）。グラフの点は1秒に10回までしか足さないので、描き直しもそれ以下（解析のコマ/秒を落とさない）。グラフの上ではなぞる操作になるので、ページを替えるときはグラフの下の行でスワイプする
    3. **数字**：顔が映っている割合・解析コマ/秒・解析時間・撮影→結果・撮影→網目・音量・声の高さ・**声の高さが取れた割合（直近10秒、声が出ていたときのうち。v1.6.2〜）**・カメラ。
       声が出ていた＝音が -60dB 以上で、直近30秒の静かなときの音より 6dB 以上大きい音の塊
  - 下に固定：家族の印（快／不快／分からない）の大きいボタン、その下に場面のボタンを1行（横にスクロールできるチップ）
  - 数字とグラフは、v1.0 ではサイドバーの「詳しい数字」にあったが、v1.1 で真ん中のページに移し、サイドバーからは消した
- **サイドバー**：iPhone（幅が狭いとき）は ≡ で左から出る引き出し、iPad・Mac（幅が広いとき）は NavigationSplitView のサイドバー
  - **いま**：撮る側ならライブの画面、見る側ならつながっている撮る側の画面。ほかの画面にしても、記録とつながりは続ける
  - **これまでの記録**：セッションごとに日時・長さ・顔が映っていた割合・違いが出た回数・家族の印の数（新しい順）。タップでリプレイ
    - 撮る側：`sessions.jsonl` の要約。「違い」の回数は記録したときの決まりで数えたもの（v1.0 より前の記録は多めに出る。リプレイでは今の決まりで数え直す）
    - 見る側（Mac・iPad）：何も保存しないので、一覧は初めは空。「記録を開く」でファイルを選ぶ画面を出し、AirDrop で受け取った `ability-cam-*.jsonl` を開く。
      開いたファイルはその場で読むだけで、どこにも写さず、メモリにだけ置く（アプリを閉じたら一覧から消える。左にスワイプでも消せる）。見る側が自動でファイルを受け取ることはない
  - **設定**
- **リプレイ**（iPhone と Mac・iPad で同じ画面のコード。`ReplayView.swift` / `Replay.swift`）：記録の JSONL を読み、映像は無いので、記録した表情の数値と顔の向きで顔の絵を動かす（撮る側と同じく約0.2秒でならす）。読むだけで、印は付けない
  - 下に「カラオケの歌詞」のような流れる時間の帯：真ん中の縦線（今の位置）は動かず、帯が右から左へ流れる。段は上から「場面」「家族の印」「いつもとの違い」（指標ごとの細い段と、表情と声の間に目を閉じているの段。アンバー＝いつもより強い・大きい・高い、青灰＝いつもより小さい・低い、墨紫＝目を閉じていた。普段が無い時間は斜線）「顔の向き」（コマから撮る側と同じ決まりで数え直したもの）。帯の長さは 30秒・1分・5分
  - 帯の下に、今の位置の出来事を大きな文字で（「家族の印：不快」「眉を寄せる動きが、いつもより強い（8秒）」「顔の向き：右へ」「場面：食事」）。次に来る出来事を1つ、薄い文字で
  - 操作：再生／一時停止（Mac ではスペースキーでも）、速さ 1倍・2倍・4倍、つまみで好きな時刻へ、前の出来事・次の出来事へ飛ぶ
  - 「いつもとの違い」は、記録の `baseline` 行（「普段を取り直す」から次の行までは比べない）と撮る側と同じ決まり（`DiffEngine.swift`）で、ファイルから計算し直す。
    `blink_masked` の無い古い `baseline` 行は、振り返りレポートと同じく目を細めるの普段をまばたきを外して数え直す。自分の記録3本と作り物の記録1本で、振り返りレポートの区間と一致することを確かめた
  - 研究用の合計（PSPI 型）はリプレイにも出さない


- **自動の記録（v0.4）**：「開始」「停止」ボタンは無い。アプリが前に出てカメラが動いている間は、自動で記録する（マイクも使う）。画面の上にいつも「記録中 12分34秒」のように経過時間を出す（薄い青灰の帯に濃紺の文字）
  - アプリを開くと、1回の記録（セッション）として新しいファイル（`ability-cam-日時.jsonl`）を始め、普段（初めは30秒）も自動で始める（v1.11 からは、開いたら「だれを記録しますか」で人を選んでから始める）。「普段を取り直す」はいつでも押せる
  - 裏に回ると、すぐカメラとマイクを止める。**5秒以内に戻れば同じセッションを続ける**（通知を見た、など）。5秒たっても戻らなければ、ファイルを閉じて要約を `sessions.jsonl` に1行足す
  - 要約を作る前に終了されたファイルは、次に開いたときに見つけて、同じ数え方で読み直して要約する（`recovered: true`）
  - サイドバーの「これまでの記録」に、セッションごとの日時・長さ・顔が映っていた割合・違いが出た回数・家族の印の数を新しい順に出す（v1.0〜。前は画面の下）
  - 前にあった「映り方チェック」と「操作がないまま5分たったらカメラを止める」は、開いている間はいつも記録するので、なくした。過去の `framing-checks.jsonl` は `analysis/framing.py` で読める
- **普段の長さ（v0.9）**：撮る側の設定で **30秒／60秒** から選ぶ（初めは30秒。v0.9 では60秒だったが、2026-10-27 の何もしない記録で比べて30秒にした：[`docs/validation-log.md`](docs/validation-log.md)）。設定を一度も変えていない端末は30秒になる。普段を記録している途中に変えると今の記録にすぐ使い（数えた分はそのまま）、記録し終えたあとに変えると次に普段を記録するとき（取り直す・次のセッション）から使う。
  使った長さは `baseline` 行の `target_s` に書く。どちらがよいかは、振り返りレポートの `--compare-baseline 30,60` で同じ記録を比べて決める
- **いつもとの違い**：記録が始まってから、**ちゃんと映っていた30秒**（設定で60秒にもできる）を「普段」として記録し（落ち着いているときに）、その後は各指標を0.3秒でならした値が普段からどれだけ離れているかを出す（z =（今 − 普段の平均）÷ max(普段の標準偏差, 下限)）。
  - **v1.0 から、振り返りレポート（`analysis/criteria.json`）と同じ決まり**（`ios/AbilityCam/DiffEngine.swift`。リプレイも同じものを使う）：
    |z| ≥ 2 が **0.5秒以上** 続いたら違いを出し、同じ向きで |z| < 1.5 が **0.5秒** 続いたら消す（ちらつかない）。表情は、直近1秒で顔が映るコマが半分以上で、かつ |yaw| < 35° のときだけ比べる。
    標準偏差の下限は 表情 0.03・声の大きさ **6dB**・声の高さ 10Hz。表情の「いつもより弱い」は今までどおり出さない
  - **目を細めるは、まばたきのコマを使わない**（v1.0〜）：eyeBlink 左右平均が 0.3 以上のコマと、その前後 0.2秒は、目を細めるを比べず、普段にも数えない。
    後ろ 0.2秒を待ってから決めるので、違いの判定は全体に約0.2秒遅れて出る。`baseline` 行に `blink_masked: true` を書く（振り返りレポートは数え直さない）
  - 普段に数えるのは、顔が読めていて（直近1秒で顔が映るコマが半分以上）、|yaw| < 35° のコマだけ。声も、その条件を満たしている間のものだけ数える（ポケットに入れる音などを入れないため）。開いてから最初の5秒は数えない（ポケットに入れる間）
  - 「普段を記録中 24/30秒」は数えた時間の合計で進む。条件を満たさない間は止まり、「顔が映るのを待っています」と出す（v0.4）
  - **目を閉じている（v1.4〜）**：eyeBlink 左右平均が 0.5 以上が **0.5秒以上** 続いたら「目を閉じている（4秒）」を、ほかの違いと同じ並び・同じ大きさで出す（それより短いのはまばたきとして数えない）。
    0.5 未満が **0.2秒** 続いたら消す。秒数は閉じ始めた時刻から数える。普段とは比べず（z を使わない）、閉じているかどうかの事実だけ。
    ほかの違いと同じく、普段がある間の、顔が読めて |yaw| < 35° のコマだけで判定する（横を向いたら打ち切る）。メーターは作らない。
    状態の名前（眠い・痛い など）は付けない。目を細めるのまばたきを外す決まり（0.3 と前後 0.2秒）は今までどおり。記録の `change` には `eyes_closed:closed` を書く
  - **普段の間に目を閉じていた時間（v1.4〜）**：普段を記録している間、普段に数えるのと同じコマで、上と同じ決まりで目を閉じていた秒数を数え、`baseline` 行の `eyes_closed_s` に書く。
    数えた時間が **10秒** を超えてから（v1.6.1〜。数え始めは短い閉じでも2割を超えるため）、その **2割** を超えたら、「いま」のページに「普段の間に目を閉じていた時間が長いです（取り直せます）」と出す（画面に出して普段を取ったときだけ。保存した普段で比べながらうしろで取っている普段には出さない）
  出すのは「眉を寄せる動きが、いつもより強い」「声が、いつもより大きい／小さい／高い／低い」といった事実だけで、状態の名前（笑顔・痛み など）や点数は出さない。意味の解釈は家族がする。「普段を取り直す」でいつでもやり直せる
- **顔が読めません**：直近1秒で顔が見つかったコマが半分未満のときは、表情の違いを出さない（声の違いは出す）
- **家族の印**：快／不快／分からない。押した時刻が記録される（家族の判断を記録する言葉。アプリが本人の状態を言うのではない）
- **続いている秒数**：「眉を寄せる動きが、いつもより強い（12秒）」のように、違いが続いている秒数を出す
- **色**：赤と赤・黄・緑の組み合わせは使わない（操作のボタンも赤にしない）。音は鳴らさない
- **網目（v0.3）**：顔の478点を MediaPipe の接続（テッセレーション・輪郭・眉・目・唇）でつなぎ、映像に重ねる。眉＝アンバー（眉を寄せる）、目＝薄紫（目を細める）、唇の外側＝空色（口角を上げる）、内側＝青（口を開ける）で（色は `docs/wording-guide.md` の指標ごとの色と同じ）、その数値（0〜1）を線の濃さにしただけ。顔が読めないときは消す。右上のボタンでオン／オフ。
  網目は解析の遅れの分だけ映像より遅れて見える（隠さない）。その遅れは「撮影→網目 ms」に出る。点の座標は記録しない
- **配置**：v1.0 からは上の「画面（v1.0）」のとおり（前は、画面の中心に大きく顔の絵、右上に小さくカメラ映像、その下に違い・家族の印・場面・数字・グラフをスクロールで並べていた）
- **顔の向き（v0.3）**：MediaPipe の変換行列から 左右（yaw）・上下（pitch）・傾き（roll）を度で求め、絵を同じ向きに動かす。絵の下に「顔の向き：右 25°・下 10°（本人から見て）」（15°未満は出さず、どれも無ければ「正面」。右・左は本人から見た向き、v1.7.1〜）。左右が35°を超えたら絵の表情部分を薄くし「横を向いているため表情は参考程度」と出す
- **顔を向ける・そむける（v0.8）**：顔が横を向いたこと自体を、事実として記録に残す（`event` の `kind: "head_turn"`）。表情の数値は横を向くと読めなくなるが、向いた・そむけた・見えなくなったことは記録できる
  - 向きは4つ（＋1つ）：**正面**（\|yaw\| < 15°）、**右**／**左**（\|yaw\| > 35°、本人から見て右が +。v1.7.1〜、それまでは映像で見て右）、**見えない**（顔が見つからない）。
    15〜35° の間では今の向きを続ける（ヒステリシス。正面から 30° を向いても「右へ」にはならず、右から 20° に戻っても「正面に戻った」にはならない）。
    見えなくなったあと 15〜35° で見えるようになったときだけ「**斜め**」にする（正面にも横にも入れないため）
  - 新しい向きが **0.5秒以上続いたときだけ** 書く（ちらつきを防ぐ）。`t_ms` は確かめた時刻ではなく、その向きになり始めた時刻
  - `value` は事実だけ：「右へ」「左へ」「正面に戻った」「見えなくなった（直前は右 40°）」「見えるようになった（左 20°）」。状態の名前は付けない
  - 開いた直後・裏から戻った直後に最初に決まった向きは、変わったのではないので書かない（カメラを止めていた間の向きは分からないので、数え直す）。顔はあるが向きが取れなかったコマは数えない
- **カメラ：広角／超広角（v0.8）**：撮る側の設定で選ぶ（初めは今までと同じ広角。超広角は `builtInUltraWideCamera`）。超広角は広く映るので、胸に着けたときに顔が画面から外れにくい。
  ただし画角の端では顔が歪み、表情の数値が変わることがあるので、使ったカメラを記録のヘッダ（`camera`）に書く。超広角が無い端末では選べない（広角のまま）。「いま」の画面の真ん中の「数字」のページに今のカメラが出る。
  - **前面（自分で試す用、v1.5〜）**：自分の顔で試すためのもの。胸に着けて使うのは背面。前面のときは上の帯に小さく「前面カメラ（試す用）」と出す（v1.11.2 でなくした。カメラは記録を始める前に最初の画面で選び、記録中は変えない）。
    - **映像の向き（v1.6.1〜、`camera_orientation_version: 2`）**：v1.5〜v1.6 は、前面に替えたとき解析に渡す映像の回転がカメラの組み替えの途中で決められていて効かず、網目が顔からずれ、roll が 40° ほどになっていた。
      v1.6.1 から、回転は組み替えが終わってから決める。背面は今まで通り 90°、前面は `AVCaptureDevice.RotationCoordinator` の水平を保つ角度（`videoRotationAngleForHorizonLevelCapture`）。届いた映像が横長なら決め直す。
      プレビューの回転と鏡は、解析に渡す映像と同じにする（網目が顔に重なる）。解析に渡す映像が鏡のとき（前面の初めの設定）は、FaceAnalyzer が記録の値を背面と同じ意味に直す：
      左右の表情の数値（`…Left` ↔ `…Right`）・yaw と roll の符号・顔の枠の中心 x・鍵となる点の x と左右。網目は画面だけなので映像のまま。顔の向きの「右」は、v1.7.1 から本人から見た右（下の「顔の向きの左右」）
    - 記録のヘッダに `camera: "front"`・`camera_orientation_version: 2`・`mirror_corrected`（記録の値を直したか）を書く（`camera` の event にも）。`camera_orientation_version` の無い前面の記録（v1.5〜v1.6）は向きが合っていなかったので、振り返りレポートが注意を出す。
      見る側に送る映像は、解析に渡す映像のまま（前面では鏡のこともある）
  記録中に変えると、すぐ切り替えて `event`（`kind: "camera"`）を書き、**表情の普段を取り直す**（広角と超広角では顔の大きさ・歪みが違い、前の普段とは比べられないため。`baseline_restart` も書く）。
  声の普段はカメラに関係ないので、v1.7 から取り直さずに続ける（`baseline_restart` に `part: "face"`）
- **顔の絵（v0.3）**：眉（眉頭・眉尻が別々）・上下のまぶたと瞳（視線は eyeLook*）・鼻（noseSneer）・上下の唇・あご（jawOpen）・耳をベジェ曲線で描いた顔が、blendshape の値（約0.2秒でならす）に比例して動く。色はやわらかい中間色で、数値によって色は変えない（長押しで 中間／明るめ／濃いめ／肌色なし を選べる）。左右は映像と同じ見え方（本人の左＝画面の右）。表情の名前・色・誇張は付けない。顔が読めないときは灰色・中立にして「読めません」とだけ出す。記録には何も足さない
- **場面**：食事／姿勢を変える／入浴・着替え／人が来た／その他。同時に一つだけ、もう一度押すと「場面なし」

## 本人の声（v1.6）
胸に着けた iPhone のマイクには、介助する人の声が一番大きく入る。また、普段を取る30秒の間に本人が声を出さないので、声の高さの普段はいつも「データ不足」だった。
そこで、声は本人の声のコマだけで比べ、声の普段は表情とは別に集める。決まりはアプリ（`VoiceSelfTracker`・`DiffEngine`）と振り返りレポート（`criteria.json` の `voice_self`・`voice_baseline`）で同じ。
- **本人の声**：声が出ている（f0 が取れている）コマのうち、顔が読めていて（直近1秒で顔が映るコマが半分以上・|yaw| < 35°）、そのコマに顔があり、
  口の数値（`jawOpen`・`mouthClose`・`mouthFunnel`・`mouthPucker`）のどれかの直近 **0.3秒** の変化（最大 − 最小）が **0.04** 以上のコマ（0.04 は仮の値。振り返りレポートの「口の動き」の分布を見て決める）。
  `frame` 行に `voice_self`（`true` / `false` / `null`）を書く
- **声の違い**（声の大きさ・声の高さ）は、本人の声のコマの値だけで判定する。本人の声と言えない声のコマでは判定しない（続いていた違いはそこで終わる）。声の言い方は今までどおり事実だけ
- 顔が読めていて口が動いていない声だけが入っているとき（直近1秒）は、「いま」に小さく「声：本人以外の声が入っています」と出す（見る側の声の欄にも）。違いには数えない
- **声の普段**：表情の30秒とは別に、開いてから5秒より後の本人の声のコマが合計 **10秒** たまったら声の普段にする（時間がかかってよい）。たまるまでは「声の高さ：普段を集めています（本人の声 4/10秒）」と出し、声のメーターにはいつもの範囲を出さない。
  `baseline` 行は表情（`part: "face"`）と声（`part: "voice"`、`voice_valid_s`）を別に書く。「普段を取り直す」と、声の普段も初めから集め直す
- **人ごとの保存した普段にも声の普段を入れる**：保存した声の普段がある人は、開いてすぐ声も比べ始める（今日の声の普段はうしろで集め、`compared: false` で書く）。

## fbank を Debug でも速く・声紋の判定を並べて記録・文字の色（v1.10.5）

- **fbank を vDSP で書き直した**：話者の計算 147ms のうち fbank が 146ms（prediction は 3ms）だった。Xcode の Debug（-Onone）で、1つずつのループが遅かったため

  Accelerate は Debug でも最適化済みなので、Mac の -Onone で 0.23ms。torchaudio との差は作り物の音で最大 0.01 未満（テスト）、話し声で最大 0.0019。

- **声紋の判定を voice_self と並べて記録する**（判定・画面は変えない）：`speaker` 行に `self_by_speaker`（選んでいる人の似ている度合いが `speaker.self_threshold` 0.45 以上で true、未満で false、選んでいる人の登録が無ければ null）。
  0.45 は仮の値（この記録の推定区間で、自分 0.7〜0.87・動画の人 -0.13〜0.27。この記録を見て決めたので、台本の記録で決め直す）。
  使った声が 1.5秒未満の行は自分でも 0.4 前後に下がるので、振り返りレポートの記録の質では 1.5秒以上の行を別に数える。

- **「声：本人以外の声が入っています」を声紋で出す**（撮る側・見る側）：選んでいる人の声の登録（今のモデル）があるときは、直近1秒に、使った声が1.5秒以上の `speaker` 行で

- **文字の色**：撮る側・見る側の「いま」の文字を、種類（表情の違い・目を閉じている・声・顔の向き・進み具合・記録の状態）ごとに色で分け、

## 話者の区別を、f0 の取れない声でも・速く動かす（v1.10.2）
記録 `ability-cam-20261029-114906`（iPhone）で分かった2つを直した。

  - 直したこと：元の重み（pyannote、CC BY 4.0）をこのリポジトリで Core ML に変換し直した（`ios/Tools/SpeakerModel/convert.py`、`ios/AbilityCam/Models/wespeaker_3s.mlpackage`、Float16、13MB。リポジトリに入れる）。
    **1行・3秒**（fbank 298×80 と、出力のフレームごとの重み 38）。fbank はモデルの外（`SpeakerFbank`、Accelerate、Float32）で求め、torchaudio の `kaldi.fbank` と同じ値か（差の最大 0.001）をテストで確かめる。
    Mac の計算の予定で **111 の演算がすべて Neural Engine**、1回 0.9ms（fbank を入れて 1.3ms。前は 17ms）
  - モデルの版が変わった（`wespeaker-r34lm-3s-fp16-v2`）ので、**v1.10〜v1.10.1 の声の登録は使わない**（設定の「人」に「前のモデルの登録なので使いません（取り直せます）」）。入力の長さが10秒から3秒になり、平均を引く範囲も変わるので、埋め込みは前と同じではない
  - 記録に `event`（`kind: "speaker_model"`）：読み込みにかかった時間・頼んだ計算の場所（`compute_units`）・演算ごとの計算の予定（`plan`：`ne` / `gpu` / `cpu` の数、iOS 17.4〜）。`perf_check.py` が並べる
- **音の設定（打ち消していないか）**：`AVAudioSession` は `category: .record`・`mode: .measurement`（自動の音量補正・ノイズ除去を切る）。`AVAudioEngine` の声の処理（エコーキャンセル）はオンにしていない。
  なので、**ほかの端末のスピーカーから流した音は、打ち消さずにそのままマイクに入る**。**同じ iPhone の中で流した音**は、`.record` がほかのアプリの音を止める（混ぜる設定 `mixWithOthers` もしていない）ので、
  記録している間は鳴らない見込み（コードと Apple の説明から。実機ではまだ確かめていない）。記録の始めに `event`（`kind: "audio_session"`）でカテゴリ・モード・声の処理・ほかのアプリの音が鳴っていたかを書く
- **本人の登録で取りこぼした声を数える**：本人を登録するとき、`voice_self` が null（f0 が取れていない）の声のまとまりを数えないのは変えない。
  そのかわり、声の大きさでは声が出ていた（計算した）が、数える 0.5秒に `voice_self: null` のコマがあって数えなかった長さを足し、`speaker_enroll_progress` に `skipped_no_f0_s` として書く
  （`voice_self: false` のコマがあったもの＝ほかの人の声は入れない）。登録し終えた・止めたときにも `final: true` の1行を書くので、5秒たまらなくても取りこぼした秒数が分かる。
  叫び声・息の多い声を、どれだけ取りこぼすかを見るため。振り返りレポートの記録の質に「数えなかった声 ○秒（数えた声 ○秒）」
- **設定「話者の区別を記録する」**：記録中に切り替えても次の記録から効くことを、トグルの下に出す（記録中は「今の記録はオン／オフのままです」も）。ヘッダに `speaker_setting`（設定の値。オンでもモデルが無ければ `speaker_on` は false）

  使った声のまとまり（最大3秒）に `voice_self: false` のコマが無く、数える分（終わりから 0.5秒）のコマがすべて `true` のときだけ足す（`SpeakerSelfGate`。3秒待ってもコマが来なければ数えない。途中で選んでいる人を変えたら数えない）。
  ほかの人を登録するときは今まで通り、声が出ている時間すべて。設定の「人」の声の登録に、どちらで集めるかを小さく出す。記録の `speaker_enroll` に `collect`（`voice_self` / `voiced`）
- **登録に必要な秒数の根拠を記録から決める**（v1.10.3 までは 30秒、v1.10.4〜 15秒）：登録している間、たまった秒数が 5秒増えるごとに `event`（`kind: "speaker_enroll_progress"`、`person_id`・`valid_s`・`score`）を書く。
  `score` は、その時点までの登録（最新の声を足す前の平均）と最新の声の似ている度合い。何秒で落ち着くかを見るため（埋め込みは書かない）。振り返りレポートの記録の質に、人ごとに「5秒 0.61、10秒 0.74…」と出す

## 話者の区別を記録に書く（v1.10、`docs/speaker-plan.md` の最初の段階）
画面には出さず、記録に書くだけ。だれの声のあとに何が変わったかを結びつけるのは、まだ作らない。
- **設定「話者の区別を記録する」**（初めはオフ。次に記録を始めたときから）。オンで、モデルがあるときだけ動く（v1.10.2〜は `AbilityCam/Models/wespeaker_3s.mlpackage`、上の「v1.10.2」）
- **音の流れ**：音のタップの中では計算しない。16kHz に変えて、輪のバッファ（メモリだけ。v1.10.2〜は3秒）に足すだけ。声が出ている（f0 がある。v1.10.2〜は、または -52dB 以上）間だけ、0.5秒ごとに、別の低い優先度のキュー（`qos: .utility`）で
  直近の声のまとまり（声が 0.3秒より長く途切れたら切る。最大3秒）の埋め込みを Core ML（CPU と Neural Engine）で求める。**1.5秒未満の短い声も計算し**、使った長さを記録に書く（0.2秒より短いものは計算しない）
- **登録**（設定の「人」の「声の登録」）：記録中で話者の区別がオンのとき、「声を登録する」→ 同意した人の名前を入れる →
  その人がひとりで話している間の声のまとまりを 0.5秒ずつ数え、合計 **30秒**（仮。v1.10.4〜 **15秒**）たまったら登録する（埋め込みを長さ1にそろえて平均したもの）。
  声の普段と同じく、初めての登録は途中の分を残して次に続きから（14日で捨てる）、取り直しはたまるまで今の登録を残し、途中の分は残さない。止める・消すもできる。
  記録には `event`（`kind: "speaker_enroll"`、`person_id`）だけを書く（名前・同意した人・埋め込みは書かない）
- **記録**：ヘッダに `speaker_on`・`speaker_model`（`wespeaker-r34lm-fluid-coreml-v1`）・`speaker_enrolled`（声を登録した人の id と役割 `self` / `family`）・`speaker_hop_s`・`speaker_max_span_s`。
  `type: "speaker"` の行（下の「記録の形式」）。振り返りレポートの記録の質に、行の数・1.5秒未満の行の数・計算時間・登録した人ごとの似ている度合いの分布を出す
- **persons.json をバックアップから外した**（`isExcludedFromBackup`、書くたびに付け直す）
- Mac で確かめる：`analysis/speaker_check.py`（アプリと同じモデル・同じ求め方で、WAV の声を分けられるか、声の長さごと）、`analysis/perf_check.py`（記録から、話者の区別のオン／オフの解析コマ/秒・撮影→結果・計算時間）

## 声の普段を集め終えたら、声の高さの範囲を戻す（v1.9.4）
- 声の高さの範囲を外すのは、声の普段を集めている間だけ。集め終えたら、選んでいる人の今の保存した声の普段の範囲を使い始める：

- 記録に `event`（`kind: "voice_pitch_range"`、`median`・`iqr`。中央値が無ければ書かず、範囲を外した）を書き、振り返りレポートとリプレイもその時刻から同じ範囲を使う
  （v1.9.3 までは、集め終えた行が `source: "today"` なので、その記録の中では範囲が外れたままだった）

## 声の普段の取り直しの決まりを揃えた（v1.9.3）
- **取り直しは、本人の声が10秒たまって保存し直すまで、保存した古い声の普段を残す**。設定の「人」から押しても、「いま」の「声だけ」から押しても同じ。
  取り直している間は、途中まで集めた分を保存しない（閉じたら捨てて、次のセッションは古い声の普段のまま）。v1.9.2 は、設定の「人」から押すとすぐ古い声の普段を消していた
- 記録していないときに設定の「人」で押したら、次のセッションの始めに集め直す（`persons.json` の `voice_retake_pending`。1回だけで、そのセッションで閉じたら古い声の普段のまま）
- 取り直している間は、声の高さの範囲を使わず、口の動き（と顔）だけで本人の声を決める。撮る側の「いま」の声の欄に「声の普段を集め直しています。この間は口の動きだけで本人の声を数えます」。
  声も取り直す `baseline_restart`（`part: "voice"` と、`part` の無い両方）からは、振り返りレポートとリプレイも声の高さの範囲を外す
- 違いの数（`sessions.jsonl` の `segments`・見る側の「違いが出た回数」）：`baseline_restart` のあと、取り直した部分の違いだけを数え直す（`part: "face"` なら表情と目を閉じている、`"voice"` なら声の大きさ・高さ、無ければ全部）。
  表情だけ取り直したときに、続いている声の違いを2回数えないため。アプリ（`SessionStats`・`AnalysisModel`）と `sessions.py` で同じ

## 普段の取り直しを、表情だけ／声だけ／両方から選ぶ（v1.9.2）
- 撮る側の「いま」の「普段を取り直す」は、押すと **表情だけ／声だけ／両方** を選ぶ。
  - 表情だけ：表情の普段を画面に出して取り直す（声の普段は続ける）。記録に `baseline_restart`（`part: "face"`）
  - 声だけ：その場で声の普段を初めから集め直す（「声の高さ：普段を集めています（本人の声 0/10秒）」）。表情の普段はそのまま。記録に `baseline_restart`（`part: "voice"`）。
    集め終えたら、選んでいる人の声の普段として保存し直す（前のセッションまでに途中まで集めた分も使わない）
  - 両方：今まで通り（`part` 無し）
- 設定の「人」の「声の普段を取り直す」：保存した声の普段と途中まで集めた分を消し、**記録中でその人を選んでいれば、その場で集め直し始める**（設定の画面に「声の普段を集め直しています」）。
  記録していなければ「次に記録を始めたときから、声の普段を集め直します」
- 振り返りレポートとリプレイも、`part: "voice"` の取り直しでは声の普段だけを消す（表情の普段はそのまま）

## 本人の声の見分けを実際の記録に合わせて直した（v1.9.1）
2026-10-28 20:25 の記録（前面、本人 4〜16秒・ほかの人 42〜51秒）で `voice_check.py` を使うと、タイミング（min_corr 0.3）は本人 45% / ほかの人 41% で見分けられず、
声の高さの範囲は保存した声の普段が 151 ± 61Hz と広すぎて、ほかの人の声の 76% を本人と言っていた。
- **タイミングの決まりは判定に使わない**（`criteria.json` の `voice_self.sync.enabled: false`、アプリの `DiffCriteria.syncEnabled = false`）。相関は振り返りレポートの記録の質にだけ出す。
  相関の求め方は、声の大きさを**映像のコマごと（約33ms）**に求め（記録に `type: "audio"` の行：音の塊ごとに `t_ms`・`block_ms`・`rms_db` の並び。音声そのものではない）、
  口の開きから **±0.2秒** ずらして（1/30 秒ごと）いちばん高い相関を取る形にした。`voice_check.py` で見直してから、判定に戻すかを決める
- **声の高さの範囲は外れ値に強い求め方**：保存した声の普段の声の高さの **中央値 ± 2.5 × ばらつき**（ばらつき＝四分位範囲 ÷ 1.349、下限 20Hz）。平均・標準偏差は使わない。
  声の普段を集めるときに声の高さの値そのものも集め（途中まで集めた分にも `f0_values`）、`baseline` 行の `f0_hz` に `median`・`iqr` を書く。中央値の無い v1.9 までの声の普段は、声の高さの範囲に使わない
- 保存した声の普段のばらつきが **40Hz** を超えるときは、「声の普段のばらつきが大きいです（取り直せます）」と出す（撮る側の「いま」の声の欄・設定の「人」）。
  設定の「人」に「声の普段を取り直す」ボタン（保存した声の普段と途中まで集めた分を消し、次に記録を始めたときから集め直す）
- `voice_check.py` は `--other 35-38,42-51` のようにカンマでつないだ時間を受け付ける。`--self-baseline` で、本人の時間の声の高さからアプリと同じ求め方で声の普段を作って試せる

## 本人の声の見分け：口の動きと声のタイミング・声の高さの範囲（v1.9）
2026-10-28 20:25 の記録（前面）で、本人が黙っているときも口の数値の直近0.3秒の変化は中央値 0.12（90% は 0.61）あり、しきい値 0.04 では、
ほかの人が話している間の小さな口の動きで本人の声になっていた（42〜51秒のほかの人の声 約320Hz が全部 `voice_self: true`。本人の声は 120〜180Hz）。
決まりはアプリ（`VoiceSelfTracker`）と振り返りレポート（`criteria.json` の `voice_self.sync`・`voice_self.pitch_range`）で同じ。**声紋（声の特徴で人を特定するもの）は作らない**。
- 声が出ている（f0 がある）コマを、次の順に見て、どれかに当たれば本人の声と言わない（記録の `voice_self_reason`）：
  1. `pitch`：その人の**保存した声の普段**があるとき（その `baseline` 行の時刻から）、f0 が 平均 ± **3** × 標準偏差（下限 **20Hz**）の外
  2. `no_face`：顔が読めていない・横を向きすぎ・そのコマに顔が無い（今まで通り）
  3. `no_mouth`：口の数値の直近0.3秒の変化が 0.04 より小さい（今まで通り）
  4. `timing`：**口の動きと声のタイミング**が合っていない。直近 **1秒** の `jawOpen` と `rms_db` の相関（ピアソン）が **0.3** より小さい（数えるコマが10より少ないときも）
- 顔が2つ映っているときは、もう1つの顔の `jawOpen`（`other_jaw_open`）でも相関を求め、どの顔の口と声のタイミングが合っていたかを `voice_match`（`self` / `other` / `none`）に書く。
  判定は今まで通り本人として選んだ顔で（将来、複数の人を分けるための下準備）
- しきい値（0.3・3・20Hz）は仮の値。本人の声の時間・ほかの人の声の時間が分かる記録で `analysis/voice_check.py` を使い、「本人の声を本人と言えた割合」「ほかの人の声を本人と言ってしまった割合」を見て決める
- 声の普段が増えない理由に「口の動きと声のタイミングが合っていません」「声の高さが本人の普段の範囲の外です」を足した
- 振り返りレポートの記録の質に、本人の声と言えなかった理由ごとのコマ数と、声のタイミングが合っていた口（本人として選んだ顔・もう1つの顔・どちらとも合っていない）を出す

## 顔の向きの普段と特徴（v1.8、記録とレポートだけ）
- 表情の普段と同じコマ（顔が読めていて |yaw| < 35°、開いてから5秒より後）で、yaw・pitch・roll（本人から見て右・上が +）の平均と標準偏差を集め、`baseline` 行の `pose`
  （`yaw_deg`・`pitch_deg`・`roll_deg` の `{n, mean, std, insufficient}`）に書き、人ごと・カメラごとの保存した普段にも入れる
- **アプリの画面にはまだ出さない**。カメラは介助する人の胸にあり、介助する人が動くと本人の顔の向きも変わって見えるため。記録を見て決める。比べる（違いにする）のにも使わない
- 振り返りレポートの「顔の向きの普段と特徴」に出す（基準は `criteria.json` の `pose`、すべて仮の値）：
  - いつもの向き（平均とばらつき）と、いつもの範囲（平均 ± 2 × 標準偏差、標準偏差の下限 5°）から同じ向きに **5秒以上** 外れていた時間の一覧（0.3秒でならす）。
    「いつもより右に傾いていた 13:42:05〜、12秒（本人から見て）」のように、向きと秒数だけ
  - 向きを変えた回数（顔の向きの段：正面・右・左・見えない・斜め。1分あたり）、ひとつの向きにとどまった長さの分布（10% / 中央値 / 90% と、2・10・30・60秒で区切った回数）、
    急な向きの変化（0.5秒で 20°以上、左右・上下・傾きのどれか。1つの動きは1回）の回数と時刻
  - 場面ごと・家族の印の前後 10秒ごとの、向きの分布（顔の向きの段の時間の割合と、yaw・pitch・roll の平均）
  - `pose` の無い v1.7 までの記録は、普段を集めた時間のコマからアプリと同じ条件で数え直す（保存した普段で pose が無いものは出さない）

## 顔の向きの左右（v1.7.1）
v1.7 までは、向かい合って見る人から見た右（映像で見て右）を「右」にしていた。前面カメラで自分を撮ると、自分が右に傾けたのに「左」と出た（実機で確認）。
- 顔の向き（yaw・roll、「右へ」「右に傾き」など）を、**本人から見た右・左**にした。前面でも背面でも、本人が自分の右へ向く・右へ傾けると「右」。表情の `…Left` / `…Right`（本人の側）とも同じ側
- 画面の言い方は「顔の向き：右 25°（本人から見て）」「顔の向きの記録（…右・左は本人から見て）」「右（本人から見て、35°超）」のように、どちらから見た右か分かるようにする（`docs/wording-guide.md`）
- 顔の絵は今までどおり映像と同じ見え方（向かい合って見る）で描く。本人が右へ向くと、絵は画面の左を向く
- 記録のヘッダに `direction_version: 2`。それより前の記録は、振り返りレポートとリプレイで読むときに左右を入れ替える（yaw・roll の符号、`head_turn` の `value`・`head`・`from`・`yaw_deg`）。
  見る側は、古い撮る側から届いた向き（`directionVersion` が無い）も入れ替えて出す
- 顔の枠（`face_cx`）・鍵となる点（`pts`）・網目は、映像の中の座標なので変えない

## 声を出す回数が少ない人に合わせる（v1.7）
声を出す回数が少ない人では、1回のセッションで本人の声が10秒たまらず、閉じると「本人の声 9/10秒」が消えていた。決まりはアプリと振り返りレポート（`criteria.json` の `voice_on`・`voice_baseline`）で同じ。
- **声の普段を、セッションをまたいで集める**：人を選んでいて、その人に声の普段がまだ無いときは、途中まで集めた本人の声（声の大きさ・高さの値の数・平均・2乗の和）を
  人ごとに保存し（`persons.json` の `voice_partial`。1秒ごとと、セッションを閉じるとき）、次のセッションで続きから足す。「本人の声 9/10秒」は閉じても消えない。
  - 古すぎる声を混ぜないように、**集め始めてから14日**たったものは捨てる（`criteria.json` の `voice_baseline.max_age_days`）。捨てたときは `event`（`kind: "voice_partial_discarded"`）を書く
  - 声の普段ができたら、途中まで集めた分は消す。`baseline` 行（`part: "voice"`）に、何回のセッション（`voice_sessions`）・何日（`voice_days`）にまたがって集めたか、前のセッションまでの秒数（`voice_carried_s`）を書く。`started_ms` は集め始めた日時
  - 記録中に人を変えたら、前の人の途中まで集めた分はこのセッションで足す前に戻し、新しい人の分から続ける。「普段を取り直す」は、このセッションで集めた分だけを集め直す（前のセッションまでの分は残す）
  - 振り返りレポートで普段を作り直すとき（`--baseline-s`）は、前のセッションの値が記録に無いので、その記録の中の声だけで集める
- **「声が出た（○秒）」を事実として出す**：本人の声のコマ（`voice_self: true`）を、間が **0.5秒** 未満ならひとまとまりにし、最初から最後までが **0.3秒** 以上なら「声が出た」（最初のコマから最後のコマまで。秒数は最初のコマから数える）。
  普段とは比べず、声の普段が無くても（表情の普段を記録している間も）出す。気持ちの名前は付けない
  - 撮る側の「いま」では、いつもとの違いと同じ並び（最後）に「声が出た（2秒）」と出す。記録の `change` に `voice_on:on` を書く
  - 見る側の「いま」に「声が出た」の行（「声が出た（2秒）」／「出ていない」）、時間の流れに「声が出た」の段（焦げ茶）。リプレイの段にも出す
  - **いつもとの違いの数（「違いが出た回数」・`sessions.jsonl` の `segments`）・通知候補には入れない**（普段と比べた違いではないため）。リプレイの要約には「声が出た ○回（○秒）」を別に出す
  - 振り返りレポート：区間の一覧と時系列に入れ、声が出た回数・長さの合計・家族の印の前後10秒に声が出ていたか（出ていた秒数）を出す
- **本人の声の見分けを、あとで見直せるようにする**（振り返りレポートの記録の質）：顔が読めているコマのうち、
  声が出ているのに「口が動いていない」と判定されたコマの割合（多いときは、口があまり動かずに声を出す人の声を取りこぼしているかもしれない）と、
  声が出ていないのに口が動いているコマの割合

## 声の高さ（f0）の求め方（v1.6.2）
v1.6.1 までは -40dBFS より小さい音で f0 を計算せず、50cm 離れた普通の声（-45〜-60dB）ではほとんど取れなかった。また 800Hz のような倍音の取り違えが混ざっていた。
決まりはアプリ（`ios/AbilityCam/Pitch.swift` の `PitchCriteria`）と `analysis/criteria.json` の `pitch` で同じ。決めた理由は `docs/validation-log.md`（2026-10-28）。
- **音の下限 -60dBFS**：これより小さい音では計算しない
- **声らしさ**：正規化した自己相関（NSDF）の山の高さが **0.6** 以上のときだけ f0 にする（雑音を f0 にしないのはこの基準。作り物の雑音では最大 0.45）
- **範囲 70〜500Hz**（話し声）。500Hz より高い音は、その半分の高さとしては出さず「取れない」にする
- **2倍・半分の取り違えを防ぐ**：一番高い山の 0.9 倍以上の山のうち周期の一番短いものを選ぶ。直近1秒の f0 の中央値から 0.75 オクターブより離れたら、中央値に近い山に替える
- 記録のヘッダに `f0_version: 2`・`f0_floor_db`・`f0_range_hz`・`f0_clarity_min` を書く（無い記録は v1.6.1 までの求め方）。
  v1.6.1 までの記録の 70〜500Hz の外の f0 は、振り返りレポートとリプレイで読むときに外す
- Mac で確かめる：`analysis/pitch_check.py 音.wav`（部屋の音だけの WAV なら f0 が 0件のはず）、`pitch_check.py --selftest`（作り物の声・雑音・範囲の外の高さ）

## 人ごとの普段（v1.2）
毎回30秒待たずに比べ始めたい。ただし前に保存した普段がその日にも使えるかはまだ分からないので、しばらくは両方を記録して比べる（`analysis/review.py --compare-saved`）。
- **人**：名前だけ（例「姉」）。人ごとにランダムな id を付ける。この端末の中（Application Support の `persons.json`。「ファイル」アプリには出ない）にだけ保存し、外には送らない。記録のファイルには id だけを書き、名前は書かない。見る側にも名前は送らない（v1.11 から、見る側には記録している人の名前だけを送る）
- **保存するもの**：普段の数値だけ（指標ごとの n・平均・標準偏差・insufficient、カメラ、普段の長さ、保存した日時、普段の間の顔の位置と大きさ、v1.6〜は声の普段も）。映像・顔の点の座標・顔の形は保存しない。顔認証はしない
- 開いたときは、前に選んだ人を使う。上の帯に名前（「さん」は付けない、v1.3〜）を小さく出し、タップで選ぶ・足す。人がいないときは「人を選んでいません」で、今まで通り動く。記録中に人を変えると `event`（`kind: "person"`、`person_id`）を書く（v1.10.5 まで。v1.11 からは人を選んでから記録を始め、変えるときは記録を閉じて新しく始める）
- **保存した普段はカメラごと（v1.6.1〜）**：人ごとに、表情の普段を広角・超広角・前面のそれぞれに1つずつ持つ（`persons.json` の `saved_by_camera`）。v1.6 までに保存した普段は、そのカメラの普段として移した。
  開いたとき・カメラを変えたときは、そのカメラの保存した普段があればすぐそれで比べ、無ければ画面に出して取り、取り終えたら自動でそのカメラの普段として保存する（ほかのカメラの普段は変えない）。
  「この普段で保存し直しますか？」も今のカメラの普段だけを置き換える。**声の普段はカメラに関係ないので人ごとに1つ**（どのカメラでも使う）。設定の「人」に、カメラごとの保存した日時と声の普段を出す（それぞれ消せる）
- **保存した普段がある人は、すぐその普段で比べ始める**（v1.3〜。設定「保存した普段ですぐ始める」はなくし、いつもこの動き）：選んだ人に保存した普段があり、カメラ（広角／超広角）が同じなら、
  開いてすぐその普段で「いつもとの違い」を出し始め、セッションの始めに `baseline` 行（`source: "saved"`、`compared: true`、`saved_ms`）を書く。
  **今日の普段は、記録のためにうしろで黙って取り続ける**（`source: "today"`、`compared: false`）。画面には「普段を記録しています」も進み具合も出さず、状態の表示は「顔：読めています・普段：保存した普段（10/28 15:10）」だけ。
  記録し終えても、比べる相手は自動では切り替えず、保存した普段も書き換えない。振り返りレポートの `--compare-saved` で、両方の普段のずれを見られる
- **今日の普段を画面に出して取るのは**、保存した普段が無い人・人を選んでいない・カメラが保存した普段と違うときだけ（今まで通り30秒、進み具合を出す）。
  記録し終えたら、その人の普段がまだ無ければ自動で保存する。カメラが違うときは保存した普段の行を書かず、`event`（`kind: "saved_baseline_skipped"`、今のカメラ `camera`・保存した普段のカメラ `saved_camera`）を残す
- **「普段を取り直す」**を押したとき（とカメラを変えたとき）は、保存した普段をやめ、今日の普段を画面に出して取り直す。取り終えたら、保存した普段がある人には「この普段で保存し直しますか？」と聞く（「保存し直す」のときだけ置き換える）
- 前の版（v1.2〜v1.2.1）：設定「保存した普段ですぐ始める」（初めはオフ）。オフの日は保存した普段の行を `compared: false` で書き、今日の普段で比べていた。保存した普段があり今日の普段を記録し終えると「今日の普段で上書き」のボタンが出ていた
- **設定「人」**：一覧から、名前を変える・普段を消す・人を消す（記録のファイルは消えない）

## 本人以外の顔（v1.2、記録だけ）
- 普段を記録している間の顔の枠（中心 x・y と幅、0〜1）の平均と標準偏差を、普段と一緒に覚えておく（`baseline` 行の `face_box`、保存した普段にも）
- Face Landmarker の `numFaces` を2にした。2つ映ったら、普段の顔の位置・大きさに近いほう（普段がまだ無いときは大きいほう）を本人として使う。`frame` 行に、使った顔の枠（`face_cx` / `face_cy` / `face_w`）を書く
- 映っている顔の数が変わって0.5秒続いたら `event`（`kind: "faces"`、`count`）を書く（最初に決まった数は書かない）
- **解析コマ/秒が落ちたら1つに戻す**：10秒ごとに、カメラから解析に渡したコマと、解析できたコマを数え、解析できたのが9割を下回ったら `numFaces` を1に戻し、`event`（`kind: "faces_limit"`、`count: 1`、理由と両方のコマ/秒）を書いて、状態の表示にも出す（映像を送っている間は見ない）。「数字」のページに「探す顔の数」と「解析できた割合（10秒）」が出る。
  解析できた割合は、顔を1つ探しているときも10秒ごとに数える（顔を1つにしたときにすでに9割を下回っていないかを確かめるため。記録には `faces_limit` のときだけ書く）
- 本人以外を外す判定は、記録を見てから決めるので、まだ入れていない（判定は今まで通り）

## 記録の形式（`ability-cam.ios.v0.2`）
1行目はヘッダ（`schema`, `started_at`, `started_at_ms`, `device`, `ios`, `camera`, `camera_label`, `note`）。
`direction_version`（v1.7.1〜は 2）は顔の向きの左右（2＝本人から見た右・左。無い記録は映像で見た右・左で、振り返りレポートとリプレイが読むときに入れ替える）。
`f0_version`（v1.6.2〜は 2）・`f0_floor_db`・`f0_range_hz`・`f0_clarity_min` は声の高さの求め方（無い記録は v1.6.1 までの求め方：-40dB 以上、70〜1000Hz）。
`person_id`（v1.2〜）は選んでいた人の id（選んでいなければ null。名前は書かない）。`camera` は記録を始めたときのカメラ（`"wide"`＝広角 / `"ultra_wide"`＝超広角、v0.8〜。無ければ広角）。`camera_label` はその日本語名。2行目からは1行1レコードで、`type` で種類を見分ける。すべての行に `t_ms`（epoch ms）がある。

### `type: "frame"`（1コマ1行）
| キー | 意味 |
|---|---|
| `t_ms` | 撮影時刻（epoch ms）。手首の記録（ability-lab.raw.v1）と並べるときに使う |
| `face` | 顔が見つかったか |
| `bs` | 表情の数値 52種（0〜1） |
| `pts` | 鍵となる顔の点（鼻先・額・あご・両目尻・両口角）[x, y, z] |
| `geo` | 顔の点の距離（v1.15〜）：`brow_eye_gap`・`brow_inner_gap`・`eye_open`・`mouth_corner`（目尻の間の距離に対する割合）。\|yaw\| > 25° のコマには無い |
| `geo_pts` | `geo` に使った点（33, 263, 105, 334, 159, 386, 145, 374, 107, 336, 13, 14, 61, 291, 10, 152 の順、[x, y]。高さを 1 とした単位） |
| `rms_db` / `f0_hz` | 音量（dBFS）/ 声の高さ（Hz。v1.6.2〜は -60dB 以上の声らしい音で 70〜500Hz、取れなければ書かない） |
| `yaw_deg` / `pitch_deg` / `roll_deg` | 顔の向き（度、v0.3〜）。**本人から見て**右を向く・上を向く・頭の上が右へ傾く が +（v1.7.1〜、ヘッダの `direction_version: 2`。それより前の記録は映像で見て右が +）。顔が無いコマには無い |
| `proc_ms` / `lat_ms` | 解析時間 / 撮影→結果の遅れ |
| `face_cx` / `face_cy` / `face_w` | 本人として使った顔の枠の中心 x・y と幅（解析した画像の中で 0〜1、v1.2〜）。顔が無いコマには無い |
| `voice_self` | 本人の声か（v1.6〜、いつも書く）：`true`＝本人の声 / `false`＝本人の声と言えない（顔が読めない・横を向きすぎ・口が動いていない・v1.9〜はタイミング・声の高さ）/ `null`＝声が出ていない（f0 が無い） |
| `voice_self_reason` | 本人の声と言えなかった理由（v1.9〜、声が出ていて `false` のコマ）：`pitch` / `no_face` / `no_mouth` / `timing` |
| `voice_corr` / `voice_corr_other` | 直近1秒の `jawOpen` と `rms_db` の相関（v1.9〜、声が出ているコマ。0.01 に丸める）：本人として選んだ顔 / もう1つの顔（2つ映っているとき） |
| `voice_match` | 声のタイミングが合っていた口（v1.9〜、声が出ているコマ）：`self` / `other` / `none` |
| `other_jaw_open` | もう1つの顔の `jawOpen`（v1.9〜、2つ映っているとき） |

v1.9.1 からは、タイミングを判定に使わないので、アプリは `voice_corr`・`voice_corr_other`・`voice_match` を書かない（振り返りレポートが `type: "audio"` の行から求める）。

### `type: "speaker"`（v1.10〜、話者の区別がオンで、声が出ている間 0.5秒ごとに1行）
| キー | 意味 |
|---|---|
| `t_ms` | 使った声のまとまりの終わりの時刻（epoch ms） |
| `window_ms` | 使った声の長さ（ms、最大 3000。1500 より短いものも書く） |
| `scores` | 声を登録した人（id）ごとの似ている度合い（コサイン類似度、0.001 に丸める）。登録した人がいなければ `{}`。**埋め込みは書かない** |
| `calc_ms` | 計算にかかった時間（ms。v1.10.2〜は fbank とモデルの合計） |
| `model` | 使ったモデルの版 |
| `f0_ratio` | そのまとまりで、声が出ていた音の塊のうち f0 が取れていた割合（0.01 に丸める、v1.10.2〜） |
| `fbank_ms` / `predict_ms` | `calc_ms` の内訳：fbank・Core ML の prediction（v1.10.3〜） |
| `wait_ms` | 声のまとまりが決まってから計算を始めるまで（キューの待ち、v1.10.3〜） |
| `self_by_speaker` | 声紋で本人の声か（v1.10.5〜）：選んでいる人の似ている度合いがヘッダの `speaker_self_threshold` 以上で true、未満で false、選んでいる人の登録が無ければ null。判定（`voice_self`）には使わない |
| `self_by_speaker_rel` | 声紋で本人の声か・ほかに登録した人と比べる（v1.11〜）：選んでいる人の似ている度合いがヘッダの `speaker_rel_min_score` 以上で、ほかに登録した人のいちばん高い似ている度合いより `speaker_rel_margin` 以上高ければ true、そうでなければ false。ほかに登録した人がいなければ `self_by_speaker` と同じ。選んでいる人の登録が無ければ null。「本人以外の声」はこれで決める |

### `type: "audio"`（v1.9.1〜、音の塊（約0.1秒）ごとに1行）
| キー | 意味 |
|---|---|
| `t_ms` | 塊の始まりの時刻（epoch ms） |
| `block_ms` | 1つの区切りの長さ（約33.3ms、映像の1コマ分） |
| `rms_db` | 区切りごとの声の大きさ（dBFS）の並び。音声そのものではない |

### `type: "baseline"`（普段を記録し終えたときに1行。取り直すたびに増える）
| キー | 意味 |
|---|---|
| `t_ms` / `started_ms` | 記録し終えた時刻 / 記録し始めた時刻 |
| `wall_s` / `valid_s` | 普段を集めるのにかかった実際の時間 / そのうち数えた時間（秒、v0.4〜）。v0.3 までの記録は `duration_s`（時計の時間で数えた長さ）だけ |
| `yaw_limit_deg` / `warmup_s` | 数えた条件：\|yaw\| がこの角度未満 / 開いてからこの秒数より後（v0.4〜、35 / 5） |
| `min_n` | 比べるのに必要なサンプル数（30） |
| `target_s` | 普段の長さ：数えた時間がこの秒数になったら記録し終える（30 / 60、撮る側の設定、v0.9〜）。無い記録は60秒 |
| `source` | `"today"`：今日の30秒 / `"saved"`：人ごとに保存した普段（v1.2〜。無い記録は今日の普段） |
| `compared` | `true`：この普段で「いつもとの違い」を比べた / `false`：記録しただけ（保存した普段で比べていた日の今日の普段）。振り返りレポートとリプレイは `true` の行だけで判定する |
| `saved_ms` / `camera` | 保存した普段：保存した日時 / 保存したときのカメラ（今日の普段にも `camera`） |
| `face_box` | 普段の間の顔の枠の `cx` / `cy` / `w`（それぞれ `{n, mean, std}`、v1.2〜） |
| `pose` | 普段の間の顔の向き `yaw_deg` / `pitch_deg` / `roll_deg`（それぞれ `{n, mean, std, insufficient}`、本人から見て。v1.8〜。比べるのには使わず、振り返りレポートだけ） |
| `part` | `"face"`：表情の普段 / `"voice"`：声の普段（v1.6〜。表情と声は別の行に書く）。無い行は両方 |
| `voice_valid_s` | 声の普段：数えた本人の声の秒数（v1.6〜、`part: "voice"` の行。v1.7〜は前のセッションまでの分も含む） |
| `voice_sessions` / `voice_days` / `voice_carried_s` | 声の普段：集めたセッションの数・日の数・前のセッションまでに集めていた秒数（v1.7〜） |
| `from_today` | 保存した普段に無かったので、今日の普段から足した指標（v1.15〜、`source: "saved"` の行）。この行の時刻から、その指標も比べる |
| `asym` | 左右の差（左 − 右、本人から見て）の普段 `brow_down` / `orbit` / `mouth_smile`（それぞれ `{n, mean, std, insufficient}`、v1.12〜。判定には使わず、振り返りレポートだけ） |
| `eyes_closed_s` | 普段の間に目を閉じていた秒数（v1.4〜。目を閉じているの決まりで、普段に数えたコマから。保存した普段の行には無い） |
| `blink_masked` | `true`：目を細めるの普段から、まばたき（と前後0.2秒）のコマを外した（v1.0〜）。無い記録は、振り返りレポートとリプレイが数え直す |
| `metrics` | 指標ごとの `{n, mean, std, insufficient}`（v1.15〜は表情の普段に値の幅 `min`・`max` も）。`insufficient: true` はデータ不足で、比べるのに使わない（n = 0 のときは mean / std なし） |

指標：`mouth_smile`（mouthSmileLeft/Right の平均）、`brow_down`（browDownLeft/Right）、`eye_squint`（eyeSquintLeft/Right）、`jaw_open`、`rms_db`、`f0_hz`（声があるときだけ）。
v1.12〜の表情のまとまり：`orbit`（max(eyeSquint, cheekSquint) の左右平均）、`nose_lip`（max(noseSneer, mouthUpperUp)）、`mouth_tense`（max(mouthPress, mouthStretch)）、`cheek_raise`（cheekSquint）。std は標本標準偏差。

| `kind` | `value` | 意味 |
|---|---|---|
| `scene` | 場面名 または `"なし"` | 場面のボタンを押した |
| `mark` | `"快"` / `"不快"` / `"分からない"` | 家族の印を押した |
| `change` | 違いの一覧（例 `["brow_down:above", "rms_db:below", "eyes_closed:closed"]`、空なら違いなし。`eyes_closed:closed` は目を閉じている、v1.4〜。`voice_on:on` は声が出た、v1.7〜。声が出たは違いの数に入れない） | 出ている違いの組み合わせ、または `face_readable`（顔が読めるか）が変わった。普段の記録が終わった直後に最初の1行 |
| `baseline_restart` | なし | 「普段を取り直す」を押した（カメラを切り替えたときも）。`part: "face"`＝表情の普段だけ（カメラを切り替えたとき v1.7〜・「表情だけ」v1.9.2〜）、`part: "voice"`＝声の普段だけ（「声だけ」・設定の「人」の「声の普段を取り直す」、v1.9.2〜）、無ければ両方 |
| `voice_pitch_range` | なし | 声の高さの範囲を使い始めた（v1.9.4〜、声の普段を集め終えたとき・保存し直したとき）。`median`・`iqr`（Hz）。無ければ範囲を外した |
| `speaker_enroll` | `"登録"` / `"取り直し"` | 声の登録を集め始めた（v1.10〜）。`person_id`、`collect`（`voice_self`＝本人の声とされた時間だけ / `voiced`＝声が出ている時間すべて、v1.10.1〜）。名前・同意した人・埋め込みは書かない |
| `speaker_enroll_progress` | なし | 声の登録の途中（v1.10.1〜）。数えた声（`valid_s`）が5秒増えるごと、本人の登録では計算した声（`computed_s`）が5秒増えるごとにも（v1.10.3〜）。`person_id`、`valid_s`、`score`（その時点までの登録と最新の声の似ている度合い。数えた声が5秒増えたときだけ）。本人を登録しているとき（`collect: "voice_self"`）は `computed_s`・`not_self_s`・`no_f0_s`・`no_frames_s`（この登録を始めてから。v1.10.2 は `skipped_no_f0_s` だけ）。登録し終えた・止めた・記録を閉じたときに `final: true` の1行（`score` なし、v1.10.2〜） |
| `speaker_model` | モデルの版 | 話者の区別のモデルを用意した（v1.10.2〜）。`compute_units`、`load_ms`（読み込みにかかった時間）、`cached`（アプリの中で前に読み込んだものを使った、v1.10.3〜）、`plan`（演算ごとの計算の予定：`ne`＝Neural Engine / `gpu` / `cpu` の数。iOS 17.4〜） |
| `audio_session` | カテゴリ | マイクを始めた（v1.10.2〜）。`audio`：`category`・`mode`・`voice_processing`（エコーキャンセルなどの声の処理）・`other_audio_playing`（始めたときにほかのアプリの音が鳴っていたか）・`mix_with_others`・`input_gain_settable` |
| `other_voice_source` | `"speaker"` / `"voice_self"` | 「本人以外の声」をどちらで決めているか（v1.10.5〜。記録の始めと変わったとき） |
| `voice_partial_discarded` | 理由 | 途中まで集めた声の普段が、集め始めてから14日たっていたので使わなかった（v1.7〜）。`person_id` |
| `head_turn` | `"右へ"` / `"左へ"` / `"正面に戻った"` / `"見えなくなった（直前は右 40°）"` / `"見えるようになった（左 20°）"` | 顔の向きが変わって0.5秒続いた（v0.8〜）。`head`（新しい向き：`front` / `right` / `left` / `hidden` / `oblique`）、`from`（前の向き）、`yaw_deg`（なり始めたときの yaw。`hidden` は見えなくなる直前の yaw）が付く |
| `camera` | `"広角"` / `"超広角"` | 記録中に設定でカメラを切り替えた（v0.8〜）。`camera`（`wide` / `ultra_wide`）が付く |
| `faces` | なし | 映っている顔の数が変わって0.5秒続いた（v1.2〜）。`count` が付く |
| `faces_limit` | 理由（解析コマ/秒） | 解析コマ/秒が落ちたため、探す顔の数を1にした（v1.2〜）。`count: 1` |
| `person` | なし | 記録中に人を変えた（v1.2〜）。`person_id`（選ばないにしたときは空） |
| `mark` の追加（v1.13〜） | | `detail`：家族の印の詳しい中身（家族が選んだ言葉。家族の言葉としてそのまま）、`detail_at`：付けた時刻（あとから付けたらその時刻） |
| `co_change` | なし | 動きの重なり（v1.12〜）。`t_ms`＝始まり、`end_ms`、`duration_s`、`above`（いつもより上か）、`metrics`（入っていた指標）、`groups`、`at_end`（記録の終わりで打ち切った）。状態の名前は付けない |
| `eyes_closed_ratio` | なし | 目を閉じている割合（v1.12〜、5秒ごと）。`ratio`・`window_s`（30）・`face_frames`・`closed_frames`。判定には使わない |
| `saved_baseline_skipped` | 理由 | 選んだ人の保存した普段があるが、カメラが違うので保存した普段の行を書かなかった（v1.2.1〜）。`camera`（今）、`saved_camera`（保存した普段） |

`change` には、どちらの普段で比べたか（`baseline`：`"today"` / `"saved"`、v1.2〜）も付く。

見る側で押した `scene` / `mark` には `source: "viewer"`、`by`（押した端末の名前）、`clock_corrected`（時計のずれを直した時刻か）が付く（v0.6〜）。撮る側で押したものには付かない。振り返りレポートの印の欄では「不快（居間の iPad で）」のように出る。

`t_ms` は押した（変わった）瞬間の時刻。`head_turn` だけは、0.5秒続いたのを確かめた時刻ではなく、その向きになり始めた時刻（そのため、ファイルの中では前後のコマより後ろに書かれる）。

## これまでの記録（`sessions.jsonl`、`ability-cam.session.v1`）
「ファイル」アプリ > このiPhone内 > Ability Cam に、セッションの記録のファイル（上の形式、1コマごとの値）と並んで置かれる。ヘッダは無く、セッション1回につき1行。1コマごとの値は入れない（元のファイルに残る）。

| キー | 意味 |
|---|---|
| `type` | `"session_summary"` |
| `file` | 記録のファイル名（`ability-cam-日時.jsonl`） |
| `started_ms` / `ended_ms` / `t_ms` | 開始（ヘッダの `started_at_ms`）／最後の行の時刻（epoch ms）。`t_ms` は `ended_ms` と同じ |
| `duration_s` | カメラが動いていた時間。コマとコマの間が1秒より空いた分（裏に回っていた間など）は1秒で切る |
| `frames` | コマ数 |
| `face_s` / `face_ratio` | 顔が映っていた時間と割合 |
| `facing_s` / `facing_ratio` | 顔が映っていて \|yaw\| < `yaw_limit_deg`（35°）だった時間と割合（横を向きすぎていなかった時間） |
| `segments` | 変化の区間の数：`change` の行で、新しく出た違いの数（アプリの画面に「いつもとの違い」が出始めた回数）。振り返りレポートの区間とは基準が違う |
| `marks` / `scenes` | 家族の印を押した回数／場面を選んだ回数（「なし」に戻したのは数えない） |
| `recovered` | 要約を作る前に終了され、次に開いたときに整理した |
| `device` / `ios` | 端末 |

要約は、記録のファイルに書いた行だけから数える（その場で作っても、あとから読み直しても同じ結果。`analysis/sessions.py` も同じ数え方）。
