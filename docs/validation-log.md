## 2026-10-28 声の普段の取り直しの決まりを揃えた（v1.9.3、v1.9.2 のコードの確かめ）
- **何を試したか**：v1.9.2（698021c）のコードを読んで確かめた
- **結果**：
  1. 取り直している間の声の高さの範囲：外していた（`AnalysisModel.restartVoice` の `voiceBox.setPitchRange(median: nil, …)`）。
     ただし振り返りレポート・リプレイは、取り直したあとも保存した声の普段の範囲を使い続けていて、アプリと違っていた。「両方」の取り直し（`resetBaseline`）では、アプリも範囲を外していなかった
  2. 取り直しの途中で閉じたとき：設定の「人」からは、押したときに古い声の普段と途中まで集めた分を消し（`PersonStore.restartVoice`）、取り直し中の分を1秒ごとに保存していたので、次のセッションはその続きからだった。
     「いま」の「声だけ」からは、古い声の普段が残っていたので途中の分は保存されず、次のセッションは古い声の普段のままだった。揃っていなかった
  3. `Session.swift` の `SessionStats.addEvent` と `sessions.py` の `baseline_restart`：違いの数（`segments`）を数えるための「続いている違い」を、part を見ずに全部消していた。
     表情だけ取り直したとき（カメラを変えたときも）、続いている声の違いを、取り直したあとの最初の change でもう一度数えていた。アプリの「違いが出た回数」も同じ
  4. 設定の「人」から取り直したとき：`PersonStore.restartVoice` → `restartVoiceFromSettings` → `restartVoice` で、`baseline_restart`（`part: "voice"`）を1行書いていた（変えていない）
- **直したこと**：
  - 取り直しは、10秒たまって保存し直すまで古い声の普段を残す（設定の「人」から・「いま」の「声だけ」から同じ）。取り直し中は `saveVoicePartial` しない。記録していないときに設定で押したら、次のセッションの始めに1回だけ集め直す
  - 取り直している間は「声の普段を集め直しています。この間は口の動きだけで本人の声を数えます」と出す。声も取り直す `baseline_restart` からは、アプリ・レポート・リプレイのどれも声の高さの範囲を外す（`PitchRangeRestartTest`：声だけ・両方では外れ、表情だけでは残る。アプリとレポートの判定がコマごとに一致）
  - `baseline_restart` のあとは、取り直した部分の違いだけを数え直す（`RestartPartTest`：両方 4件・表情だけ 3件・声だけ 3件）
- **まだ確かめていないこと（実機で）**：取り直しの途中で閉じて開き直すと、設定の「人」の声の普段の日時が前のままで、「いま」が保存した声の普段で比べ始めること。
  記録していないときに設定で押すと、次に開いたとき「声の高さ：普段を集めています（本人の声 0/10秒）」から始まること

  振り返りレポートとリプレイも、`part: "voice"` では声の普段だけを消す（作り物の記録に入れて、声の区間だけが出なくなり、アプリとレポートの区間が一致することを確かめた：`VoiceRestartTest`）

## 2026-10-28 本人の声の見分けを、実際の記録の結果に合わせて直した（v1.9.1）
- **何を試したか**：2026-10-28 20:25 の記録（前面、実機）で、v1.9 の `voice_check.py`（本人 4〜16秒・ほかの人 42〜51秒）
- **結果**（v1.9 の決まり）：

  | 決まり | 本人を本人と言えた | ほかの人を本人と言ってしまった |
  |---|---|---|
  | 口の動きだけ | 97% | 96% |
  | ＋タイミング（min_corr 0.3） | 45% | 41% |
  | ＋声の高さの範囲（保存した声の普段 151 ± 61Hz） | 97% | 76% |

  （`--other 35-38,42-51` はカンマで落ちていた）
- **分かったこと**：
  - タイミング（直近1秒の jawOpen と rms_db の相関）は、本人とほかの人で同じくらいの割合で通り、見分けられていない。v1.9 では声の大きさを約0.1秒ごとの値のまま映像のコマに並べていて、口とのずれも見ていなかった
  - 保存した声の普段の声の高さのばらつきが 61Hz と大きく、平均 ± 3 × 標準偏差では 0〜330Hz くらいまで本人の範囲になっていた（声の普段を集める間に、高い声・低い声も出していた）
- **決めたこと**：
  - タイミングは判定に使わない（`sync.enabled: false`）。相関はレポートだけ。声の大きさを映像のコマごと（約33ms、記録の `type: "audio"`）に求め、口の開きから ±0.2秒ずらしていちばん高い相関を取る形にした。
    作り物の記録（声が口より 0.13秒遅れる）では、ずれを探すと相関の中央値が 0.9 を超え、ずれは 0.13秒前後と出た（ずれを探さないと 0.1 以上低い）
  - 声の高さの範囲は 中央値 ± 2.5 × ばらつき（四分位範囲 ÷ 1.349、下限 20Hz）。作り物の 150 ± 10Hz の声に 400Hz・80Hz を1割ずつ混ぜても、中央値は 150 ± 5Hz、ばらつきは 18Hz 以下（標準偏差なら 60Hz を超える）
  - 保存した声の普段のばらつきが 40Hz を超えたら「声の普段のばらつきが大きいです（取り直せます）」。設定の「人」に「声の普段を取り直す」
  - v1.9 までに保存した声の普段（中央値が無い）は、声の高さの範囲に使わない。今の 151 ± 61Hz の声の普段は、取り直すまで声の高さの範囲では外さない（注意は標準偏差で出す）
- **まだ確かめていないこと（この記録を Mac に置いて）**：
  1. `python voice_check.py ability-cam-20261028-2025*.jsonl --self 4-16 --other 35-38,42-51 --self-baseline` で、新しい声の高さの範囲（本人の時間から中央値・四分位範囲で作った声の普段）の2つの割合。
     「ほかの人を本人と言ってしまった」が 1割より高ければ k_spread（2.5）を下げる
  2. 同じ表の「タイミングだけ min_corr=…」（±0.2秒のずれを探す新しい求め方）。ただしこの記録には `type: "audio"` の行が無いので、コマの rms_db で求めた値になる。
     v1.9.1 で取り直した記録で、本人とほかの人の割合に差が出るかを見てから、判定に戻すかを決める
  3. 実機で声の普段を取り直し、設定の「人」で声の高さの中央値・ばらつきが出ること、ばらつきが 40Hz 以下になること

## 2026-10-28 本人の声の見分けに、口の動きと声のタイミング・声の高さの範囲を足した（v1.9）
- **何を試したか**：2026-10-28 20:25 の記録（前面、実機）で、本人が黙っているときの口の数値の直近0.3秒の変化は中央値 0.12（90% は 0.61）。

  | ＋タイミング（min_corr 0.3） | 100% | 0% |

     「本人を本人と言えた」が 8割より低ければ min_corr を下げ、「ほかの人を本人と言ってしまった」が 1割より高ければ上げる。決めた値と2つの割合をここに書く
  2. 実機で、ほかの人が話している間に「声：本人以外の声が入っています」が出て、本人が話すと声の普段が増えること
  3. 2人映したとき、記録の `voice_match` が話している人の顔になっていること

- **何を試したか**：実機（iPhone を顔から約50cm）で普通に話した4分の記録（2026-10-28）。あわせて、Mac にあった v1.0 より前の記録（iPad、2026-10-27〜28 の 7本）の音量、

- **結果**：
  - 実機の4分の記録で f0 があったのは 105コマ。声の普段の「本人の声 0/10秒」が増えなかった。取れた値に 800Hz・842Hz が混ざっていた
  - 原因：v1.6.1 までは RMS が 0.01（-40dBFS）未満だと f0 を計算しなかった。50cm 離れた普通の声は -45〜-60dB。範囲は 70〜1000Hz で、倍音（声の高さの2倍・3倍の周期）を取り違えても外せなかった
  - Mac の記録の音量（話していない時間を含む）：中央値 -50〜-52dB の記録が5本（p5 -55〜-60）、-63.5dB と -84.5dB が1本ずつ。**部屋の音だけで -55dB を超える部屋がある**ので、音の下限だけでは雑音を除けない
  - 作り物の雑音（白色・ピンク・ブラウン・扇風機のような低い音と 120Hz のうなり・電源のうなり 50Hz・離れた話し声のような揺れる音）を -55・-50・-45・-35dB で各20秒：
    新しい求め方の声らしさ（正規化した自己相関の山の高さ）は最大 0.45（扇風機のような音）、ほかは 0.27 以下。**f0 は 0件**。
    v1.6.1 までの求め方のまま下限だけ -60 に下げると、ピンクの雑音で 53件、ブラウンで 74〜92件 が f0 になった（10秒ずつ）
  - 作り物の声（pink の雑音 -68dB を足す。声らしい塊のうち f0 が取れた割合）：

    | 声の音量（塊の中央値） | 下限 -55dB | 下限 -60dB |
    |---|---|---|
    | -50dB | 0.85〜0.98 | 0.92〜1.00 |
    | -55dB | 0.59〜0.70 | 0.80〜0.95 |
    | -60dB | 0.00〜0.23 | 0.62〜0.71 |

    どちらも、大きい声で取った値と比べて 2倍・半分の取り違えは 0件。500Hz より高い値は 0件（v1.6.1 までの求め方では、同じ声 -45〜-55dB で 577件中 46件が 500Hz より高かった）
  - 扇風機のような音 -62dB を足した声 -45〜-55dB でも、2倍・半分の取り違えは 0件、取れた割合 0.84
- **分かったこと**：雑音を f0 にしないのは、音の下限ではなく声らしさの基準の役目。下限 -55 では、平均 -55dB の声の3〜4割を下限で捨てていた
- **決めたこと**（`criteria.json` の `pitch`、アプリの `PitchCriteria`。ヘッダに `f0_version: 2`・`f0_floor_db`・`f0_range_hz`・`f0_clarity_min`）：
  - **音の下限 -60dBFS**（依頼の -55 より下げた。上の表の理由）。これより小さい音では計算しない
  - **声らしさ 0.6**：正規化した自己相関（NSDF、McLeod の方法）の「鍵となる山」の一番高いものが 0.6 以上のときだけ f0 にする（雑音は最大 0.45）
  - **範囲 70〜500Hz**（話し声）
  - **2倍・半分の取り違えを防ぐ**：一番高い山の 0.9 倍以上の山のうち周期の一番短いものを選ぶ（半分の高さにしない）。それが 500Hz より高ければ f0 にしない（650Hz・900Hz の音を 325Hz・450Hz と出さない）。
    直近1秒の f0 の中央値（3つ以上）から 0.75 オクターブより離れたら、中央値に近い山（一番高い山の 0.7 倍以上）に替える
  - v1.6.1 までの記録の 70〜500Hz の外の f0 は、振り返りレポートとリプレイで読むときに外す（記録の質に「使わなかった値 ○件」）。Mac の記録では 2本で 15件・3件
  - 「数字」に「声の高さが取れた割合（直近10秒、声が出ていたときのうち）」を出す。声が出ていた＝音が -60dB 以上で、直近30秒の静かなときの音（下から1割）より 6dB 以上大きい音の塊（部屋の音が -60dB を超える部屋で、部屋の音を分母に入れないため）
  - 声の普段の進み具合が3秒増えないときは、直近3秒で一番多かった理由を出す：「顔が読めていません」（顔が読めていない）／「声の高さが取れていません」（顔は読めていて f0 が無い）／「口が動いていません」（f0 はあるが口が動いていない）
- **まだ確かめていないこと（実機で）**：
  1. 話していないときの部屋の音（エアコン・冷蔵庫・テレビ）で、「声の高さ Hz」が出ないこと（「数字」で「–」のまま）。電源のうなり 100Hz のような周期のはっきりした音は、声らしさでは除けない
  2. 50cm 離れて普通に話して、「声の高さが取れた割合」が 7割以上になり、声の普段の「本人の声」が増えること
  3. 声の高さの値が話している人の声の高さに近いこと（女性 150〜350Hz・男性 80〜200Hz くらい）、800Hz のような値が出ないこと
  4. 解析コマ/秒が落ちていないこと（f0 の計算は約0.1秒ごと）

## 2026-10-28 前面カメラの向きを直し、保存した普段をカメラごとにした（v1.6.1）
- **何を試したか**：実機の前面カメラで顔をまっすぐ映すと、網目が顔からずれて左下に斜めに出て、顔の向きが「右に傾き 41°」になった（v1.6）

  - 回転は、組み替えが終わってから決める。背面は今まで通り 90°。前面は `AVCaptureDevice.RotationCoordinator` の水平を保つ角度。届いた映像が横長なら決め直す
  - 鏡はカメラの初めの設定のままにし、プレビューを解析に渡す映像と同じ回転・鏡にする。解析に渡す映像が鏡なら、記録の値（左右の表情・yaw と roll の符号・顔の枠の x・鍵となる点）を背面と同じ意味に直す

- **確かめ方（実機で、まだ）**：

  4. 右目だけ閉じる → 背面で人を撮って本人の右目を閉じたときと同じ側（`eyeBlinkRight`）が上がる

  - 声の普段はカメラに関係ないので、人ごとに1つ（どのカメラでも使う）
  - 「普段の間に目を閉じていた時間が長いです」は、数えた時間が10秒を超えてから判定する
